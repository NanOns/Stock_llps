# Stock A 实现详细设计

## 1. 范围

本文只描述现役仓库中已找到的CLI、API、PG读取实现及其真实业务消费者。产品目标仍为全市场画像、市场→板块→个股、变化识别和持续跟踪；本文不把尚未接通的目标写成已实现能力。金融公式、窗口、单位、坐标和质量规则以 [算法合同与升级规则](算法合同与升级规则.md) 为准。

## 2. 现役架构

业务入口在 src/stock_a/application；PG适配在 storage/postgres；HTTP路由和固定资源服务在 service；领域函数位于 canonical、research、sources等单一业务包；页面资源独立位于 web/product。配置从config/runtime.defaults.json和登记的合同资源读取。

当前价格字段机器合同为config/contracts/price-profile.contract.json，拆成来源字段、Core字段、Profile字段三个经结构与字段规则校验的模块，只登记运行时实际消费的价格语义。

来源路径由现有CLI读取授权源、检查输入和解析Raw，仅在TDX原始下载包接收入口校验并登记一次包字节SHA-256；随后按数字source_package_id、精确日期、来源代码和数字source_capture_id写入stock.source_raw_daily。source_packages保存包入口字节校验，source_captures保存解析合同、实际捕获时钟和行数。下游不存储、传递或查询摘要字段。原始来源根保持只读。

Core根据明确目标日及实际可用历史Bars计算，Profile组合Core字段形成个股技术画像；行业/GN目录与成员关系由TDX分类来源独立提供，两链通过来源股票代码的实际交集用于板块研究。当前画像表保留历史主键及多个修订；普通视图按来源、生产者语义、日历、窗口、坐标和质量确定适用画像，无法唯一确定时局部标UNKNOWN。Raw和独立结构研究不以画像存在为前置。

全池Seed消费者使用的`core.ret1`、`core.ret5`与`core.liquidity_mean20`随画像保存精确值、质量及原因；收益率单位为fraction，流动性均值以CNY为合同单位，来源金额单位未证实时保持UNKNOWN。新增字段通过前向迁移加入，旧修订的空列不冒充已计算，新语义使用独立画像修订。

已应用迁移原件保持不变，并按迁移编号、已应用状态与lineage保持顺序；迁移账本不保存或验证迁移源码SHA。0016现有文件仍按仓库原样保留，不因本批改写。

## 3. CLI现状

唯一正式入口由stock-a与python -m stock_a共享，详细命令参数以当前 --help 和 parser_registration 为准。研究命令有显式日期/截止、来源代码、数字来源包ID或本机授权路径参数。TDX包SHA仅在包接收/导入校验内部使用，不作为CLI业务参数。生产命令不可从本地步骤推断或自动触发。

已有研究消费者包括：
- source-raw读取精确Raw日线和捕获/内容事实；
- research-stock单股指标、周期和变化解释；
- research-universe-preview来源候选检查；
- D0 Raw新增/变化观察、D1突破回踩和市场/板块Raw计算；
- 从PG读取已保存的精确Profile，用于趋势关系和两日期变化。

`source-research-day`是同一正式CLI中的离线D0/D1单日生产命令。它从现役官方交易日历确定相邻前态，复用现役D0 `LAUNCH_CONFIRM`变化计算与`prepare_d1_material_observation`的五类D1结构/锚变化计算，并把逐股结果投影为typed facts。默认dry-run只读PG；仅显式`--persist`允许写入。`--static-only`未指定`--persist`时拒绝执行。静态画像窗口按同日、同来源及现行语义的完整已存画像确定，多个合格窗口须以`--history-session-count`消歧。画像修订保留算法版本，并以可逆的日历标识、日历修订和请求会话数区分不同实际输入；多种现行修订同时存在时不得自动选择。`--workers`可显式选择有界进程数；证券独立计算在子进程执行，PG连接、全池排名和写入留在主进程。画像表与静态事实表的现存数据库约束仍限制窗口为1至75会话，超过此范围的持久化需后续集中迁移；不得把当前计算窗口当成有效Bar数量。初始化和后续日更调用同一生产者，日期、截止、来源包与算法必要窗口显式传入。

新入参以日期、数字来源包ID和Profile显式修订选择画像。TDX原包SHA仅在包接收校验入口使用，不进入画像查询。现存数据库主键由单列BIGINT IDENTITY承担，存量画像经父Raw数字ID与短业务唯一键精确读取；缺失或不唯一时返回具体错误。

旧Seed事实可能遗漏收益字段；读取时仅从同来源捕获、同目标日、同窗口与精确画像修订的已存Profile补充收益，并标明字段来源。无法匹配时保留有原因的未知状态。前一RPS端点分母只从该端点完整已存事实取得；未保存时明确标记`NOT_COMPUTED`，不以当日分母或共同证券数代替。新Seed投影保存收益的精确值或未知原因；常规同键异值仍拒绝覆盖。Codex按当前明确任务判断已存旧行是否需要物理纠错，不另设逐对象授权门，并须核对来源业务键、事务结果和独立读回。

## 4. PG事实与消费者

| 关系/数据 | 当前用途 | 处理 |
|---|---|---|
| stock.source_raw_daily | Raw读取、单股、D0/D1、宽度和成员研究 | 保留事实；用数字来源捕获/包ID及精确日期、证券和短业务键读取 |
| stock.source_packages / source_captures | TDX原始包入口校验，以及数字包ID、解析合同、实际捕获时钟和行数 | 保留来源包父记录与实际捕获事实；唯一package_sha256只在TDX接收校验入口使用 |
| stock.source_symbol_price_profiles | Profile11及两日期筛查/变化 | 保留已保存画像；单列BIGINT IDENTITY为主键，Raw数字父ID和显式Profile修订维持真实版本差异 |
| stock.source_d0_launch_day_facts | D0相邻三态、具名原因与转移 | R06新增前向迁移；每日期/来源/捕获/算法/会话合同/来源股票一行 |
| stock.source_d1_structure_day_facts | 每股五类结构状态、输入质量、锚状态分母与typed坐标 | R06新增前向迁移；每日期/来源/捕获/窗口/日历/生产者/股票/结构类型一行 |
| stock.source_d1_material_anchor_day_facts | 材料变化与质量锚、出生/前后来源、坐标和原因 | R06新增前向迁移；以父D1结构行的业务键、锚标识和出生会话关联 |

当前行业/GN成员仍从`tdx_sector_members`的精确快照读取并在查询时JOIN，结果明确为NON_PIT；不创建成员副本。市场/板块汇总由上述typed事实及成员快照SQL聚合。业务完整性由同一事务、唯一键、D0并集计数、D1逐股五类计数和父子锚明细数验证，不另建日级完成表。实际迁移应用及消费者接通情况须以物理核验为准。

PG catalog核对必须只读，并报告当前迁移版本、真实外键、唯一约束和数据日期范围。历史迁移文件若已应用，保持原件和迁移顺序不变；当前迁移账本仅记录连续编号、应用时间和lineage。Codex按当前任务和实际依赖判断是否需要物理DROP或ALTER，不设逐对象审批；如确属解决任务所需，先核实引用和影响范围，再按可恢复事务执行并独立读回。

## 5. API行为

服务只从固定端口127.0.0.1:28766提供开发预览；GET保持只读。产品静态资源只允许static_assets.py列出的路径。页面必须由服务资源白名单实际提供，不依赖来源本地文件直接渲染。

价格画像关系筛查端点为GET /api/source-symbol-price-profile-relation-screen。前后日期、数字来源包ID和画像revision精确绑定；relation_field为必填，transition_type缺省为ALL，offset缺省为0、limit缺省为50。after_amount_ratio20_min与after_volume_ratio20_min同时出现时按AND筛选。total_count为完整匹配数，offset/limit控制真实分页；非法参数返回4xx和中文原因。

单股Raw/Core预览、官方会话轨迹、周/月周期、市场来源分页、两日关系和现存D0变化入口保持各自业务语义。Raw日期与数字来源包ID精确绑定，不由后台latest替换；TDX包SHA仅在原始包接收校验入口使用。GET `/api/product/research-day`调用`read_source_research_day()`读取精确PG事实；未应用迁移或该日未完成时明确返回`NOT_COMPUTED`，不触发算法回退。现役全池消费者应读取完成的PG事实，不能以源码存在替代实际接通与读回验证。Codex依据当前任务自主确定必要PG操作，涉及旧数据时核实确切业务键与影响，使用事务并做独立读回；不逐对象申请批准。

变化对象的单股解释可打开后续价格事实：固定T0、数字来源包ID、来源代码和研究截止，按官方会话读取最多10个后继；逐项展示同包Raw合法OHLC、缺失原因，以及合法同坐标收盘的精确相对变动。截止外的会话标为NOT_AVAILABLE，缺Bar不推断停牌，不向前借价。此入口属于HISTORICAL_NON_PIT_EXPLORATION、RAW_UNADJUSTED后验观察，不是复权收益、交易收益或正式Forward，且不改变D0/D1判断。

## 6. UI显示

页面启动从PG真实Raw日期目录选择不晚于研究截止、完整且唯一的最新来源日；全站只有一个研究日期选择器，切换时取消或隔离旧请求并清除旧详情、分页和结果。市场→行业/GN→股票为浏览路径；D0新增、D1支撑及D1材料变化分别展示，结构与原因筛选只影响对应研究范围。算法输入历史窗口不由事件时间线的展示区间或T+N后继期限决定。实际未接通或输入不足的部分显示NOT_COMPUTED、UNKNOWN或NON_PIT，不以其他来源级结果替代。日期、来源、单股搜索、历史图表和变化详情驱动已接通API。

浏览器验收只使用Codex内置浏览器，并实际操作日期切换、搜索、分页、展开/折叠等适用功能。必须通过正在运行的本次源码服务观察可见数据和交互。静态DOM或HTTP 200不能代替页面验收。

## 7. 新能力边界

需求中的全市场画像、市场→板块→个股、变化识别、持续跟踪和前瞻验证继续保留。部分实现只按真实CLI/API/PG/UI证据报告其范围。真实历史成员、身份、来源available_at或PIT缺失时，只将依赖这些证据的字段标UNKNOWN或NON_PIT，不妨碍可独立计算的价格画像。
