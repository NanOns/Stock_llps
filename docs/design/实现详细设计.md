# Stock A 实现详细设计

## 1. 范围

本文只描述现役仓库中已找到的CLI、API、PG读取实现及其真实业务消费者。产品目标仍为全市场画像、市场→板块→个股、变化识别和持续跟踪；本文不把尚未接通的目标写成已实现能力。金融公式、窗口、单位、坐标和质量规则以 [算法合同与升级规则](算法合同与升级规则.md) 为准。

## 2. 现役架构

业务入口在 src/stock_a/application；PG适配在 storage/postgres；HTTP路由和固定资源服务在 service；领域函数位于 canonical、research、sources等单一业务包；页面资源独立位于 web/product。配置从config/runtime.defaults.json和登记的合同资源读取。

当前价格字段机器合同为config/contracts/price-profile.contract.json，拆成来源字段、Core字段、Profile字段三个经结构与字段规则校验的模块，只登记运行时实际消费的价格语义。

股票价格路径通过明确的数据初始化/日更任务读取BaoStock，并将未复权`adjustflag=3`与前复权`adjustflag=2`分别作为来源代码×交易会话×坐标的typed价格事实保存，同时登记真实查询捕获身份、捕获时钟、字段、单位与质量。每批任务明示自己的价格证券总体和截止范围；业务实现不固化临时总体。不得伪造TDX ZIP包或capture身份表示BaoStock查询。TDX只读取远端行业/GN目录和成员，并按其真实快照身份保存。规范价格事实的物理表名由同批前向迁移与唯一Reader实现确定；旧TDX价格包/捕获字段不得继续作为新价格链的消费键。原始来源根保持只读。

Core根据明确目标日及实际可用历史Bars计算，Profile组合Core字段形成个股技术画像；行业/GN目录与成员关系由TDX分类来源独立提供，两链通过来源股票代码的实际交集用于板块研究。当前画像表按`(target_session, source_symbol)`保存单一当前有效画像（改变历史窗口参数重算时事务替换当前结果），普通视图按日期与来源代码直接读取，无法计算时局部标UNKNOWN。Raw和独立结构研究不以画像存在为前置。

全市场成交参与归约使用精确市场宽度来源分母和同捕获QFQ画像。单个来源代码的画像历史窗不足时保留`HISTORY_ROW_NOT_STORED`，在成交参与中以`PROFILE_HISTORY_WINDOW_INCOMPLETE`计为UNKNOWN；仍披露完整来源分母与可评估分母，不因局部历史缺口中止整个会话，也不把未知折算为零。

全池Seed消费者使用的`core.ret1`、`core.ret5`与`core.liquidity_mean20`随画像保存精确值、质量及原因；收益率单位为fraction，流动性均值以CNY为合同单位，来源金额单位未证实时保持UNKNOWN。新增字段通过前向迁移加入，旧修订的空列不冒充已计算，新语义使用独立画像修订。

已应用迁移原件保持不变，并按迁移编号、已应用状态与lineage保持顺序；迁移账本不保存或验证迁移源码SHA。0016现有文件仍按仓库原样保留，不因本批改写。

## 3. CLI现状

唯一正式入口由stock-a与python -m stock_a共享，详细命令参数以当前 --help 和 parser_registration 为准。研究CLI与来源命令按当前登记解析；股票研究只读取BaoStock价格事实或其PG消费者，不注册本地TDX股票日线诊断命令。旧TDX ZIP摘要不得作为BaoStock价格CLI或业务键；生产任务只从明确的运营菜单或正式CLI参数启动，不从本地步骤推断或自动触发。

已有研究消费者包括：
- source-raw按精确BaoStock捕获读取Raw日线和内容事实；
- 产品API读取单股价格、周期和变化解释；
- D0 Raw新增/变化观察、D1突破回踩和市场/板块Raw计算；
- 从PG读取已保存的精确Profile，用于趋势关系和两日期变化。

`source-research-day`是同一正式CLI中的离线D0/D1单日生产命令。它从现役官方交易日历确定相邻前态，复用现役D0 `LAUNCH_CONFIRM`变化计算与`prepare_d1_material_observation`的五类D1结构/锚变化计算，并把逐股结果投影为typed facts。默认dry-run只读PG；仅显式`--persist`允许写入。`--static-only`未指定`--persist`时拒绝执行。静态画像窗口按同日、同供应方和现行价格坐标语义的唯一已存画像确定；`--history-session-count`作为显式计算窗口参数记录并在参数变化时替换该日有效结果。`--workers`可显式选择有界进程数；证券独立计算在子进程执行，PG连接、全池排名和写入留在主进程。持久化字段仍受smallint范围、官方日历窗口、闭合价格事实覆盖和资源预算约束；实际有效Bar数按对象质量计算，不等于请求会话数。初始化和后续日更调用同一生产者，日期、截止、价格坐标与算法必要窗口显式传入。

纯D0启动内核输出的`D0_SESSION_BAOSTOCK_QFQ_R3`标识其计算窗口与QFQ输入语义；来源级D0聚合及PG事实采用`D0_SESSION_R2`作为持久化会话合同。R3仅保留为内核诊断元数据，不复制进PG的session_contract或正式准入键；正式准入Reader按R2精确读取。

同一CLI的`--formal-admission-from-saved --persist`模式只枚举显式范围内已经闭合的LAUNCH D0事实；它不重算Raw/D0、不采集来源，也不扩展到无D0事实的日期。每个目标会话核对Raw捕获、D0分母、Core/Profile/Seed画像修订与官方窗口，再将完整分母逐行送入`STOCK_A_D0_EVENT_ADMISSION_R1`，写入`stock.source_d0_formal_admission_day_facts`。相同业务键、相同内容可重跑；相同业务键异内容回滚拒绝。正式Focus和个股GET只读取并分页这些已完成事实，未计算、未闭合、零READY及单行准入原因分开表达。D0单股Raw读取继续标记DIAGNOSTIC；该模式以闭合的已存D0场景事实作为FORMAL准入评估输入，不改写原始事实。用户界面按字段显示真实价格坐标：当日实际价格为`RAW_UNADJUSTED`，PHC20跨日冻结线为BaoStock QFQ `FORWARD_ADJUSTED`；`SOURCE_SYMBOL_ONLY`和`NON_PIT_EXPLORATORY`不等于官方证券身份、严格历史PIT或交易资格。只有真正READY的LAUNCH事件可保存T0严格前20会话PHC20冻结线及下一官方会话生效日；其它状态不保存候选冻结线，也不实现RECOVERY、PULLBACK、CONTINUE或D2生命周期。

新入参以日期、实际价格捕获身份、价格坐标和Profile显式修订选择画像。TDX历史原包SHA不进入新价格画像查询。现存数据库主键由单列BIGINT IDENTITY承担，来源/画像父子关联须使用经迁移确认的真实capture业务键与短唯一键精确读取；缺失或不唯一时返回具体错误。

旧Seed事实可能遗漏收益字段；读取时仅从同来源捕获、同目标日、同窗口与精确画像修订的已存Profile补充收益，并标明字段来源。无法匹配时保留有原因的未知状态。前一RPS端点分母只从该端点完整已存事实取得；未保存时明确标记`NOT_COMPUTED`，不以当日分母或共同证券数代替。新Seed投影保存收益的精确值或未知原因；常规同键异值仍拒绝覆盖。Codex按当前明确任务判断已存旧行是否需要物理纠错，不另设逐对象授权门，并须核对来源业务键、事务结果和独立读回。

PG catalog核对必须只读，并报告当前迁移版本、真实外键、唯一约束和数据日期范围。历史迁移文件若已应用，保持原件和迁移顺序不变；当前迁移账本仅记录连续编号、应用时间和lineage。Codex按当前任务和实际依赖判断是否需要物理DROP或ALTER，不设逐对象审批；如确属解决任务所需，先核实引用和影响范围，再按可恢复事务执行并独立读回。

## 5. API行为

R08/业务11继续只使用“数据初始化”和“数据日更”两个菜单。初始化支持价格事实复用补算与二次确认的全业务事实重置；合法历史会话数是动态参数，Core/Profile窗口及研究输出窗口依消费者确定。预览盘点PG全部业务表/行数和FK，保留安装身份、迁移账本、运行配置及当前任务；删除前验证BaoStock合法目标价格字段/坐标与可重建性，并验证行业/GN概念成员只读来源，合法无Bar保持UNKNOWN。PG事务内重新核对确认指纹、表行数及FK；中断后从已提交步骤续跑，不再次清空。手动日更按SOURCE、BASE、RESEARCH选择模块及输出窗口；`SOURCE_ONLY`仅完成BaoStock价格与TDX成员来源层，不启动研究生产者，`FULL_THREE_LAYERS`仅表示全部实际接通生产者。各来源及研究模块分别记录状态和异事务读回；未由协调器执行的消费者显示未计算或未实现。请求键绑定模式、模块、输出/输入窗口、日历修订、真实来源捕获与价格坐标。

执行方式为补缺、范围重算、派生清理、清理后重算。局部安全清理登记每个已接通基础/研究模块的确切源表、算法版本、捕获、日期及下游非外键SQL依赖；版本混合或依赖未闭合时阻断并说明合并清理范围。清理只处理选定派生事实，Raw及来源原件不参与普通派生清理。全库重置显式列出固定业务表集合并执行单事务`TRUNCATE TABLE`，不使用`CASCADE`；外键清单和保留对象预检失败时拒绝。事务级TEMP只暂存当前重置任务与进度，事务内恢复该任务并记录逐表行数与CLEARED状态。提交后独立PG核验表范围。重置后任务从已提交来源与模块步骤继续，不重复清空。重置前置来源核验不通过时不执行任何删除。

两页通过data-jobs计划API按官方日历与显式截止形成只读计划，通过GET读取PG任务、阶段和每个实际业务表的进度，并只经本机Origin受限的显式POST启动任务。计划与GET不采集、不写行情；PG写入任务使用必要事务和异事务读回。行业/GN PULSE采用同一观察时刻的类型化快照对并显式标记`NON_PIT`；其PULSE、相邻变化及截至cutoff已到期后继复用现有typed表和Reader。无合法快照显示未计算，未来后继显示`NOT_DUE`，禁止任务截止后的行情请求。真实来源范围由当前任务明确授权，不启用正式日更调度。

服务只从固定端口127.0.0.1:28766提供开发预览；GET保持只读。产品静态资源只允许static_assets.py列出的路径。页面必须由服务资源白名单实际提供，不依赖来源本地文件直接渲染。

价格画像关系筛查端点为GET /api/source-symbol-price-profile-relation-screen。前后日期按单一当前有效画像精确绑定；relation_field为必填，transition_type缺省为ALL，offset缺省为0、limit缺省为50。after_amount_ratio20_min与after_volume_ratio20_min同时出现时按AND筛选。total_count为完整匹配数，offset/limit控制真实分页；非法参数返回4xx和中文原因。

单股RAW/Core预览、官方会话轨迹、周/月周期、市场来源分页、两日关系和D0变化入口保持各自业务语义。价格日期与adjustflag坐标精确绑定，不由多版本选择器并存；TDX历史ZIP/SHA不用于新价格查询。GET `/api/product/research-day`只读取单一当前有效PG事实；未应用迁移或该日未完成时明确返回`NOT_COMPUTED`，不触发算法回退。现役全池消费者应读取完成的PG事实，不能以源码存在替代真实接通与读回验证。必要PG操作执行事务并独立读回。

变化对象的单股解释可打开后续价格事实：固定T0、来源代码、供应方价格捕获/坐标和研究截止，按官方会话读取最多10个后继；逐项展示同坐标OHLC、缺失原因以及合法收盘的精确相对变动。截止外的会话标为NOT_AVAILABLE，缺Bar不推断停牌，不向前借价。后验供应方前复权观察标记NON_PIT，不冒充当时已知价格或正式Forward，且不改变D0/D1判断。

## 6. UI显示

页面启动从PG真实Raw日期目录选择不晚于研究截止、完整且唯一的最新来源日；全站只有一个研究日期选择器，切换时取消或隔离旧请求并清除旧详情、分页和结果。市场→行业/GN→股票为浏览路径；D0新增、D1支撑及D1材料变化分别展示，结构与原因筛选只影响对应研究范围。算法输入历史窗口不由事件时间线的展示区间或T+N后继期限决定。实际未接通或输入不足的部分显示NOT_COMPUTED、UNKNOWN或NON_PIT，不以其他来源级结果替代。日期、来源、单股搜索、历史图表和变化详情驱动已接通API。

浏览器验收只使用Codex内置浏览器，并实际操作日期切换、搜索、分页、展开/折叠等适用功能。必须通过正在运行的本次源码服务观察可见数据和交互。静态DOM或HTTP 200不能代替页面验收。

## 7. 新能力边界

需求中的全市场画像、市场→板块→个股、变化识别、持续跟踪和前瞻验证继续保留。部分实现只按真实CLI/API/PG/UI证据报告其范围。真实历史成员、身份、来源available_at或PIT缺失时，只将依赖这些证据的字段标UNKNOWN或NON_PIT，不妨碍可独立计算的价格画像。
