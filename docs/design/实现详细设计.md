## 3. R00解码与精确复权

### 3.1 TDX日线

字节协议继承现有解析器：32字节小端`<IIIIIfII`，依次为日期、O/H/L/C整数、float32金额、uint32量、reserved。价格整数除100；量/金额的规范单位必须由来源合同声明和实际来源核验，不能只凭协议整数形状推断所有源单位相同。

通达信官网完整`hsjday.zip`的中央目录使用`sh/lday/*.day`、`sz/lday/*.day`、`bj/lday/*.day`相对路径，不保证带`vipdoc/`前缀。校验器同时接受这两种已知根路径；无记录证券可有零字节`.day`占位项，该项计入文件覆盖但不得当成有效行情或送入Core。交给现役来源读取器时，在G盘临时提取区补齐`vipdoc/`根，ZIP原始成员名仍单独记录。

```python
def decode_day_record(raw32, unit_contract):
    require(len(raw32) == 32 and unit_contract.is_bound)
    date_i, o_i, h_i, l_i, c_i, amount_f, volume_i, reserved = unpack(raw32)
    session_date = parse_real_calendar_date(date_i)  # 日期格式不等于官方交易日
    prices = exact_prices(o_i, h_i, l_i, c_i, divisor=100)
    price = validate_ohlc_group(prices)  # 非法/零占位→本组空值与隔离原因
    amount = validate_amount_independently(amount_f, unit_contract)
    volume = validate_volume_independently(volume_i, unit_contract)
    return DecodedDay(session_date, price, amount, volume, reserved)

```

日期重复、逆序、同实体同日异内容必须显式冲突；不以字典后写覆盖。零价格占位不伪造actual或停牌；停牌需要独立状态来源。来源读取只读，解码错误带record offset及类别，不输出整源字节。

#### 有界单遍扫描与只读文件入口

`sources.tdx.day.decode_day_record`仍是唯一32字节解码器。`sources.tdx.day_stream`增加`ReadLimits`、`LocatedDay`、`DayReadError`、`DayRecordScan`和`iter_day_records(readonly_stream, units, limits)`；`sources.tdx.day_source.open_day_file(source_path, source_roots, units, limits)`只负责受控打开、实际句柄验证和最终变化检查，并把同一`DayRecordScan`的结果包装为带来源身份的摘要，不另实现文件Reader。

`ReadLimits.max_bytes`、`max_records`、`chunk_records`为拒绝bool的正整数，`max_seconds`为有限正数；`chunk_records`上限32768条。限制由调用方显式提供，32768条仅限制单次读取块，不是全文件大小默认值。扫描器只调用带正上界的`read(n)`，允许短读并以`b''`判EOF；不seek、不关闭调用方流、不保存全文件记录。它只保留一个读取块、最多31字节余尾、前一条已解码记录/原始记录和固定计数，以单遍SHA-256覆盖实际读到的所有字节。

每个`LocatedDay`的`record_index`从0起、`byte_offset=32*record_index`，`decoded`直接复用现有`DecodedDay`。日期须为有效公历日期且严格递增；相邻同日按规范已知字段差异区分`SAME_DAY_CONFLICT`与`DUPLICATE_DATE`，未知组无法证明相同时明确报告未知组，reserved字节变化不冒充业务字段冲突；首次倒退立即以`NON_INCREASING_DATE`停止，不构造全历史日期集合。坏OHLC、金额、数量沿用现有分组质量及原因并分别计数，不改变记录总数。

扫描摘要仅在读到EOF、记录结构与预算通过且最终检查成功后可读；提前break、close或任一异常都使`summary`报`SCAN_NOT_COMPLETE`，已yield前缀不是完整文件。达到字节/记录上限时最多额外读取1字节区分恰好EOF与超限；超限不yield越界记录，也不生成完整SHA或成功摘要。每次读取、每条记录和最终检查均检查单调耗时预算；系统调用永久阻塞时Python循环无法强制中断，返回后再识别超时。时间字段是带本机时区的`read_started_at`/`read_completed_at`，不代表来源可用或封口时钟。

文件入口要求非空显式绝对`source_roots`及绝对候选路径，路径组成而非字符串前缀判根。它只以只读权限打开普通文件；Windows来源边界读取真实文件句柄最终路径和文件身份，不能证明时以`SOURCE_HANDLE_UNVERIFIED`拒绝。打开前记录路径/句柄身份、大小及修改时点；EOF最终检查相同句柄、当前路径绑定、身份、大小和修改时点，差异以`SOURCE_CHANGED`拒绝。原生HANDLE交给`open_osfhandle`前由来源边界负责关闭；成功后descriptor归其所有者，只有`fdopen`成功后流对象接管descriptor。任一接管步骤失败，只关闭当时仍由本边界拥有的资源一次；`CloseHandle`按Windows `HANDLE`/`BOOL`签名声明。调用方上下文退出、失败或提前退出时文件句柄关闭；清理关闭失败不得覆盖正在传播的原始异常，仅当原始异常提供可调用的`add_note`时附加清理错误说明，以兼容Python 3.10；无原始异常时关闭失败按来源I/O错误报告。来源目录不写日志、缓存或旁车文件。该异常清理语义见CHG-024。

稳定错误码包含空文件、尾记录、非法日期、重复/冲突/逆序、来源路径与权限、句柄不可验证、来源变化、预算/超时、流合同错误及未完成扫描。错误带中文说明、原因类别及已知记录位置，不带原始记录字节。摘要仅含计数、首尾日期、字节数、原始字节SHA、单位版本、分组质量/原因计数和必要来源句柄检查身份；它不是`SOURCE_CAPTURED`、`INGRESS_ONLY`、SOURCE seal或业务接受版本。

文件句柄复核提供对可观测路径/身份/大小/修改时点变化的工程检测，不构成普通文件的不可变快照；恶意并发写入并恢复全部可观察元数据不在保证范围。字节SHA只描述本次实际读到的字节，不证明来源/PIT时钟。详细采用决定见CHG-018。

### 3.2 GBBQ协议与类别1解释

`sources.tdx.actions.decrypt_block`保留旧16轮解密数学体和4176字节协议常量；模块不导入旧项目。固定协议版本为`TDX_GBBQ_29B_V1`，类别1单位版本为`TDX_XRXD_UNIT_R1`。`decode_gbbq_bytes(content, *, source_ref, protocol_version, unit_version, max_bytes, max_records)`只接受调用方提供的`bytes`和显式合同，不读文件、配置、HTTP或数据库。`source_ref`必须非空且仅定位这次输入，不代表业务主键或捕获/可用/封存时钟；预算为拒绝`bool`的正整数。

包头是小端uint32记录数，总长必须精确等于`4 + 29*N`。每条记录前三个8字节块分别调用唯一`decrypt_block`，末5字节原样保留。先检查字节/记录预算和整包长度，再构造有限记录集合；合法空包是4字节零计数头，缺头、超预算、声明长度不闭合及尾字节均为结构错误。解析结果保留声明计数、解析计数、输入顺序、重复行和逐条`source_record_index`；`source_byte_offset=4 + 29*index`。GBBQ日期不要求全局递增，不排序、去重或按字典覆盖。

市场字节0/1/2映射为SZ/SH/BJ；代码区必须是六位ASCII数字并以NUL填充。拼成的`source_symbol`只表示来源市场/代码，`identity_status`不签发稳定`security_id`。事件日期只验证公历有效性，不推断交易日、上市日、官方来源时钟或PIT；每行`pit_status`明确为`NOT_ASSERTED`。记录质量、身份解析状态、PIT状态和类别语义分别保存；非法市场/代码/日期或非有限参数保留记录与偏移并标出原因，不静默缩小分母。

类别1的`c1/c2/c3/c4`依次表示每10股现金分红(CNY/每10股)、配股价(CNY/股)、送转数量(股/每10股)、配股数量(股/每10股)，单位固定由`TDX_XRXD_UNIT_R1`声明。float32按其实际二进制值转为`Fraction`，不经十进制显示文本或舍入。类别1四值须有限且非负，`10+c3+c4`须为正；零现金、零配股价、负零和全零参数按合同保留。`xrxd_fields()`只对数据有效的类别1记录提供精确字段。协议已知类别2–14保留行/类别/参数但语义状态为未支持；其他类别标为未知，均不得当成无事件或恒等仿射。

每个参数的`parameter_quality`只表达数值是否可观测：有限float32成功解码为精确`Fraction`时是`OBSERVED`；NaN或正负Infinity保留为`None`并标`UNKNOWN_DATA`。`OBSERVED`不代表参数通过类别合法性检查。`parameter_reasons`逐字段记录该参数的解码或语义错误：非有限值为`C*_NON_FINITE`；类别1有限负值仍保留其精确负`Fraction`、质量为`OBSERVED`，并在对应字段记录`C*_NEGATIVE`。类别1负值原因同时进入整行`reasons`，使`data_quality=INVALID_DATA`并阻断`can_interpret_xrxd`及`xrxd_fields()`；同一行其他合法参数值、质量和原因不受影响。字段原因只标记所属参数，跨字段约束`10+c3+c4<=0`仍作为整行原因记录。类别2–14及未知类别不套用类别1非负约束；类别1消费者仍按类别语义拒绝它们。`UNKNOWN_DATA`和字段原因是不同维度，禁止把已知非法值改写成缺失或零。

`ContractError`表示缺失或错误的调用合同；`GbbqDecodeError`带稳定`code`及已知记录序号/字节偏移，表达包结构/预算或类别消费者拒绝。逐行可定位数据问题记录为质量及原因而不是整包异常；程序错误不包装为来源缺失。该纯解析接口不读取实际TDX源、不签发身份/PIT或来源准入，也不计算仿射系数。正式行为见CHG-019。

### 3.3 本地仿射

每10股分红cash、送转bonus、配股rights、配股价rights_price：`m=(10+bonus+rights)/10`，`c=(cash−rights*rights_price)/10`，理论除权价`(P−c)/m`。参数按原生协议精度解释，使用Fraction或等价精确Decimal；事件类别不支持时不得当1/0恒等事件。

```python
def build_target_view(dates, native_events, target_session, source_cutoff):
    events = validated_events_known_by(source_cutoff)
    events = [e for e in events if e.effective_session <= target_session]
    require_no_ambiguous_same_day_event_order(events)
    ordered = sorted(events, key=lambda e: (e.effective_session, registered_same_day_order(e)),
                     reverse=True)
    event_cursor = 0
    alpha, beta = exact(1), exact(0)
    for day in reversed(sorted_unique(d for d in dates if d <= target_session)):
        while event_cursor < len(ordered) and ordered[event_cursor].effective_session > day:
            event = ordered[event_cursor]
            m, c = exact_event_parameters(event)
            require(m > 0)
            alpha = alpha / m
            beta = beta - alpha * c
            event_cursor += 1  # 每个事件只合成一次，不在更早日期重复应用
        yield coordinate_factor(day, alpha, beta, full_event_dependency_ref)
    # 每个价格最终按已绑定tick一次HALF_UP；中间事件不逐步舍入
```

逆变换`P_origin=(P_target−beta)/alpha`；差值/ATR换基只乘正尺度，不加beta。Anchor原值及事件不改写；观察视图另算。无确定换基返回PRICE_BASIS_MISMATCH，不能退回RAW比较。算法合同R4明确的允许价格域和未知事件影响范围继续适用。

正式纯接口为`canonical.adjustment.AdjustmentContext`、`XrxdEvent`、`UnsupportedAction`、`event_from_gbbq`、`build_affine_factor`、`affine_price`、`inverse_affine_price`、`transport_difference`、`adjust_ohlc`及`round_to_tick`。当前只支持`RAW:`源坐标、`ADJ:`正式目标坐标和`RESEARCH:`精确研究目标坐标；目标模式由`coordinate_mode`明确选择。正式模式`TICKED`在factor内绑定正tick，并在目标身份中包含该tick；价格调用省略tick仍按绑定tick舍入，显式重复tick必须与绑定值相同。研究模式`EXACT_RESEARCH`保留精确有理结果、不作量化，且只能使用独立`RESEARCH:`坐标身份。factor携带tick、模式、参数版本及producer版本；当前仅接受`TDX_XRXD_UNIT_R1`和`STOCK_A_AFFINE_R1`，未知版本明确拒绝。目标坐标身份由坐标名、模式、正式tick（研究模式为空）及producer版本构成；改变任一字段均产生不同身份，不允许在同一正式factor上改tick。`adjust_ohlc`遵循同一绑定语义。调用还必须绑定稳定`security_id`、目标会话及带时区`source_cutoff`；源bar会话由每次`build_affine_factor`明确提供。`event_from_gbbq`只消费R00.04有效类别1行，effective_session与available_at必须由已验证调用方注入，绝不从GBBQ event_date或文件名推导。来源symbol不参与实体绑定。

`adjust_ohlc_field(field, factor, source_coordinate_id=...)`是纯质量投影边界：输入字段为UNKNOWN_DATA或NOT_APPLICABLE时保留原FieldValue与原因，同时返回因子目标坐标摘要；OBSERVED字段经`adjust_ohlc`完成同因子转换。源坐标必须精确等于factor.source_basis。坐标摘要按PRICE_COORDINATE_R1和factor.target_coordinate_id确定性编码，包含目标坐标名、模式、正式tick（研究模式为空）和producer版本。此适配不负责来源选择、实体/日期权威、PG typed写读或生产消费绑定。

`build_affine_factor`只接收`tuple`或`list`事件序列，默认最多1000项，调用方可降低或提高预算但不得超过10000项；在复制、校验、排序前检查容器类型、预算类型和值及序列长度。超限整批拒绝，不返回部分factor。未定位事件错误只报告受影响事件数，不拼接无界引用列表。该界限是输入合同，不代表全市场性能验收。factor的`event_source_refs`按事件顺序保存实际消费的`event_ref`、`source_ref`及可用的记录序号/字节偏移；这是来源引用闭包，不是内容digest或缓存能力。GBBQ事件适配同时保留原单位版本；直接构造的合成事件没有GBBQ记录位置。

`UnsupportedAction`仅表示协议已知但本项目不支持的类别2–14；未知类别保留为GBBQ解析错误状态，不可手工标成已知不支持动作。

事件只有在`available_at <= source_cutoff`且`effective_session <= target_session`时已知并生效；从d到T只应用`d < effective_session <= T`，所以除权日RAW不重复调整。截止后才知道及目标日后才生效的事件不进入本次因子。一个有效会话只有单事件时可省略同日顺序；多个事件必须各有不同的非负注册顺序，组合按事件顺序，不使用GBBQ记录位置推断。重复`event_ref`一律拒绝。已知实体/会话且跨越范围内的`UnsupportedAction`拒绝该窗口；窗口完全在其生效会话之后则不受它阻断。`UnresolvedAction`仅用于实体或会话尚未确认的事实：知识截止内且仍可能影响当前窗口时保留其不确定范围并拒绝计算；已确认属于其他实体或已确认在窗口外时不影响当前窗口。不得臆造为其他实体事件或静默忽略未定范围。

类别1采用`m=(10+bonus+rights)/10`、`c=(cash-rights*rights_price)/10`。逐事件精确合成`alpha=alpha/m`、`beta=beta-alpha*c`（使用更新后的alpha）；系数不舍入。RAW输入价格必须为正；仿射后的历史坐标允许非正值，不能夹断或epsilon替代。任何收益消费者须独立要求两个同目标坐标端点均为正后才可求收益。价格仅在最终目标坐标按正tick执行整数有理数HALF_UP一次，负tie远离零；量化不承诺逆变换无损。OHLC先用四个精确RAW值校验正值与开高低收包络，再应用同一仿射factor，并仅在最终目标坐标量化一次；差值、ATR和区间宽只乘alpha，amount/volume留在原单位。所有数值拒绝bool、float、NaN、Infinity及非法tick；输入对象不变。无真实来源/时钟绑定的合成事件只可标识为合成研究上下文，不构成LIVE/PIT证明。

### 7.2 支撑有序转换

只评t−1已存在的锚。令同坐标zone=[lo,hi]、Aprev>0：touch与带缓冲区交叠；close_breach=C<lo−0.5Aprev；deep_breach=C<lo−1.5Aprev；eod_reclaim=touch且C>=hi且CLV>=0.5。以下按顺序first-true：

| 优先级 | 条件 | 新观察/状态与计数 |
|---|---|---|
| 1 | 原BROKEN/INVALIDATED | 保留终态；恢复须新事件，不能复活旧锚 |
| 2 | 创建当日或尚未到最早后继会话 | IDLE，不增加test_count |
| 3 | actual/换基/所需ATR或前态证据缺失 | UNKNOWN观察、保留last_known+STALE；连续计数清零，累计test_count保留 |
| 4 | deep_breach或连续2个相邻可评估close_breach | BROKEN，记录关联episode失效事实 |
| 5 | 单次close_breach | BREACHED_SHALLOW，名称不作盘中先后宣称 |
| 6 | qualified separated_retest且eod_reclaim | HELD_CONFIRMED；test_count按新测试段增加，已进入RETESTING不重复加 |
| 7 | 首次eod_reclaim，或前TESTING/BREACHED_SHALLOW且eod_reclaim | RECLAIMED；首次touch计1，reclaim不另加 |
| 8 | 前RECLAIMED且后续至少1个actual C>=hi、无breach | HELD_TENTATIVE |
| 9 | 前HELD_TENTATIVE/HELD_CONFIRMED，再touch但未reclaim | RETESTING |
| 10 | 其余touch | TESTING |
| 11 | 无touch且到zone距离<=1Aprev | APPROACHING |
| 12 | 其余合法观察 | 保留有效前态或IDLE |

separated_retest：已有首次测试，之后至少一个actual会话完全不touch，再touch；分离资格被此次测试消费。若已进入合格RETESTING，下一相邻可评估touch会话允许reclaim完成该次复测，资格不能无限跨未知日保留。实际field需保存prior_retest_qualified、prior_separated_sessions、prior_adjacent_evaluable，不可仅保留状态枚举丢掉资格。停牌/未知断连续与分离资格，不算一次离带。

### 7.3 突破接受与留存

acceptance依次：已硬失效→BROKEN；必需观察未知→UNKNOWN；创建后连续2个相邻可评估会话C>=upper→ACCEPTED；创建后可评估会话不足2→PENDING；其余→NOT_ACCEPTED。创建当日不计。连续守住用于acceptance，不能直接产生支撑HELD_CONFIRMED。

## 12. 可选FEP的不可丢失设计

FEP是独立可选能力，失败不阻断Core；不能把下面方法摘要当成已冻结的完整模型实施合同。沿用旧FEP R2的关键方法，旧DDL/旧权限/旧stage不直接迁入。

- ENTRY、DAILY_LANDMARK、MARKET_WIDE、Sector/Rotation、Market观察单位分开；ENTRY不能冒充今日候选预测。每target/horizon/variant独立可评估性，Label只读Forward权威，不另写一套结算。
- 特征cutoff、原事实可见、训练成熟、label修订可见、每fold cutoff、训练/校准完成、模型接受/激活、预测开始/接受/deadline分列。早fold只取当时可见revision；今日训练回放旧日期属于历史模拟。
- ABS_RETURN、market/sector excess、MFE/MAE/MDD_CLOSE、ATR路径、FIRST_EXIT、ANY事件、trend transition分别注册。ATR路径回撤为价格差回撤/A0，不等于MDD_ratio除(A0/P0)。FIRST_EXIT为吸收式首事件，ANY事件允许重叠；未到N或中间观察缺口不能填NONE。
- 同日期横截面不拆fold；FIT/TUNE/CALIBRATION/OUTER_TEST各有截止，全部预处理只fit训练段。按label事件端点、可见/成熟/修订时钟及共享episode逐边界purge，不仅留固定gap。被调参使用过的测试窗口不能重新算独立晋级证据。
- 条件统计base partition固定entity_type/scope/signal/target/horizon/variant/evidence/label政策/合同版本；backoff依次L4=base+regime+trend+position+risk、L3=base+regime+trend+risk、L2=base+regime、L1=base，按支持度首个满足层选，禁止按收益正负选层。
- 条件桶B内部重新按日期平权：w_i=1/(D_B*n_dB)，均值sum(w_i*y_i)，观察正收益频率sum(w_i*I(y_i>0))；加权分位数为累计权重首次>=q的最小有序y。不能沿用全scope权重导致桶内权重和小于1。
- 支持度同时看行数、日期、时间块、实体、episode及类别数；complete-case明确只代表可观察子集，缺失/OOD/漏预测均留在原分母。不把重叠行数当独立样本数，不把分布p25/p75当模型置信区间。

- 模型部署制品只来自可信发布过程、校验格式/摘要，不反序列化不可信pickle；不由每日增量生成业务模型文件。预测、slot、必要特征/label引用等日常状态使用必要PG行，保留有界模型版本及资源预算。

训练窗口/支持度/实验预算/阈值/提升标准等仍须在独立FEP实施合同中确定，未确定仅方法继承；R00–R07不为此铺空模型表或假预测。

## 14. 来源首捕与运行身份的实际绑定

盘后通达信完整包由`stock_a.sources.tdx.vipdata`适配器显式读取官网`https://www.tdx.com.cn/article/vipdata.html`、独立元数据脚本`https://data.tdx.com.cn/vipdoc/_hsjdayinfo.js`与配置登记的ZIP对象`https://data.tdx.com.cn/vipdoc/hsjday.zip`；三个地址统一登记在唯一`runtime.defaults.json`的`source_policy.vipdata_official`中。页面HTML没有嵌入ZIP链接或更新日期时，不据此推断数据源缺失；真实更新时点以脚本中的`HSJDAY_SOFT_TIME`为准，页面HTML解析结果仅作旁证。`source-vipdata --mode inspect`有界读取页面和元数据，记录页面与元数据各自观测时钟、元数据SHA、官方更新时间及配置ZIP对象；只有目标会话通过随包交易日历且官方更新时间不早于目标时才进入下载候选。`download-verify`最多识别并响应一次官网静态Cookie挑战，不执行响应JavaScript；随后有界下载数据包并校验响应长度、SHA-256、ZIP中央目录、entry预算及CRC。官网包允许`sh|sz|bj/lday/*.day`和兼容的`vipdoc/`前缀，证券代码为六位数字或大写字母数字组合；零字节`.day`作为空占位计数但不送入Scanner/Core。第三方/降级重定向、未知文件族、非空非32字节倍数条目和路径逃逸均拒绝。可选`--consume-symbol`只将用户明示的已校验条目交给现有`open_day_file`、Canonical只读选择和`calculate_core`，输出仍为NON_PIT研究事实。该适配器不自动连接来源目录、不写PG或业务持久文件、不封口/接受来源，也不替代P01真实捕获。

阶段0的北交所`vipdoc/bj/lday`为可选诊断。BJ目录缺失、样本损坏或可选预算用尽时返回`OPTIONAL_DEFERRED`并保留SH/SZ已完成样本；若SH/SZ所需扫描本身失败，仍按原错误分类阻断。BJ未知文件数不填成0，也不进入沪深主板/创业板候选分母。

只读源可能被TDX更新：读取前后记录文件身份/大小/mtime与有界读过程，完整字节摘要/记录计数/规范摘要验证；检测读取过程中变化则拒绝seal并有界重试，不能混合两个文件版本。mtime与文件名日期只作诊断，不证明早先可见时钟。Bao登录/请求/解析/完整校验时钟及所有重试计入预算，原始响应不常驻。

PG保存内容摘要、规范必要事实、解析合同/源范围及actual_read_started_at/validated_complete_at/提交确认事实；实际时间未知则明确UNKNOWN。源事实写入提交后再记录commit_observed_at，seal等待该确认；该时钟是已观察提交的保守上界，不冒称精确WAL刷盘瞬时。下载后到落PG之间崩溃时允许重试/重采，不能倒填早时钟制造PIT。真实LIVE首捕还需当时已接受依赖/截止、持久观察及不可改写关联；有内容SHA但缺可信当时捕获链，只能NON_PIT/LATE或历史重建。

来源二进制不入PG、不默认生成每日源副本。实际读取的必要PG事实及来源链足以恢复已接受历史，不保证以后能恢复未保留的全部原字节；严格原字节举证能力缺失须披露，不以PG规范摘要冒充原件。重要已有用户原件只读保护；需要额外原件保留的特定能力应在来源合同明确有界用途，不能借审计复活每日业务文件。

## 15. 首次来源持久化的最小物理关系设计

R01前向迁移`migrations/0003_r01_source_identity_canonical.sql`是本节设计的首个最小执行源码，**仅准备、未执行；当前PG中是否已有对象须独立只读核对**。它只准备来源内容/首捕、身份观察/稳定实体、单日日历与Canonical typed关系；不含原始字节或通用payload。R00不建表；R02因子/画像/Owner/索引/接受关系由机器字段注册展开typed列、PK/FK/CHECK及索引计划后再进入迁移。不得先建全产品表，也不得用单个payload表顶替未完成DDL。所有关系实际迁移需工程规范S27.7的真实stock_a登录、业务身份与数据引用约束验证；数据库环境由同一业务账号访问，不以登录角色隔离。

`src/stock_a/postgres_typed.py`提供Canonical选择字段到价格/金额/数量typed组的纯映射、证据校验签发入口、稳定语义revision，以及SourceCapture/身份/Canonical参数化SQL计划与精确读回；模块不建立连接、不执行SQL。官方BaoStock基本资料目前只提供证券代码与上市区间等补充事实，未提供稳定security_id，故只能生成PROVISIONAL/UNMAPPED观察，不能签发OFFICIAL_STABLE。稳定身份签发验证器只接受明确稳定ID来源合同；BaoStock与TDX的量额验证结果按字段、来源代码、目标日和源摘要绑定，未知字段在typed候选中为空，不能沿用调用方倍率。合成签发仅用于验证路径可达，产出的候选禁止生成正式PG写入计划。字段revision绑定值、质量/原因、单位证据语义和来源解析合同/价格坐标；组合revision另绑定稳定实体身份、日历和三个字段revision。完整原件SHA与capture ID只作来源追溯，其中捕获时钟不进入旧日语义修订。`canonical_daily_readback_plan`及对应SourceCapture/Identity读回用于未来单独授权写入后的精确核对；相同修订读到不同payload、身份/日历或来源capture引用必须报冲突，不能由`ON CONFLICT DO NOTHING`静默成功。当前状态为`SOURCE_AND_TYPED_SQL_PREPARED_NOT_CONNECTED`，不表示表已建、迁移已执行或数据已写入。

研究预览中的Bao `tradeStatus`只投影为Bao报告的目标日状态；TDX Bar状态独立记录为`PRESENT`、`TARGET_MISSING`、`READ_FAILED`或`NOT_EVALUATED`。只有研究入口实际评价了目标日Bar后，才生成联合解释枚举。Bao报告交易且TDX有Bar时明确为`BAO_TRADING_TDX_BAR_PRESENT`；无Bar时记为`BAO_TRADING_TDX_BAR_MISSING`的来源冲突；Bao报告停牌但TDX有Bar时保留价格并标冲突。来源不可用、状态未知、TDX读取失败和未评价分别保留，不互相降格或覆盖。Bao身份补充仅由`research-stock --include-baostock-identity`显式触发，一次有界登录读取基本资料与指定日名录；普通查询不联网。其观察时间是本次捕获时钟，回查旧交易日仍为`NON_PIT_RETROSPECTIVE`，不构成稳定身份、首捕可得时钟或正式上市分母证明。

迁移SQL以`migrations/0003_r01_source_identity_canonical.sql`为唯一可执行结构定义；本设计不再维护第二份DDL，避免列、约束和中文注释分叉。迁移当前仅包含来源内容/首捕、稳定实体与身份观察、单日日历、Canonical typed行和必要范围索引；capture commit observation、session status、jobs/checkpoints、leases及后续R02关系不在本迁移内，仍是未来设计/实施依赖，未因本节描述而视为已建或已验收。有限数域会拒绝NaN与无穷值；字段单位、跨字段语义及正式表写入仍需应用层证据和后续受控验收。

源分块写采用同事务typed行+checkpoint，未完整来源摘要时使用明确未seal的临时capture/候选绑定；最终校验完成再写最终content/capture及接受关联，不虚构最终SHA。未seal暂存用固定限定表/受控TEMP，不按任务建表；中断时只保留必要已提交typed候选和游标。实际R01需选择并实现候选暂存到最终关系的事务/引用方案，不能仅靠本SQL忽略streaming临时身份。

### 15.1 分字段质量与空间边界

采用唯一同业务键typed行方案，不另建价格/量额平行Reader。价格组四值全有且OHLC合法，或四值全空并带明确原因；金额和数量各自独立，质量不是交易状态。价格坏的行可以保存合法量额，但不能变成actual价格bar；未知与确认停牌仍由独立session_status判定，不能跳过未知日期凑窗口。坏量额不影响合法价格聚合，price坏不抹掉合法量额。DATA_INVALID属于隔离原因，空值质量为UNKNOWN_DATA，不把程序异常包装为缺数据。

新增三组quality/reason/revision，来源FK共用该记录实际capture，revision不嵌捕获时间或文件位置。所有未知/NA必须有非空原因，OBSERVED必须有值且无缺失原因；零量额是合法已知。源记录长度/日期/身份无法确定仍拒整条，不把无法定位的数据挂到任意日。源协议/单位合同缺失报BLOCK_CONTRACT。

R01最小索引不变，不给quality/reason额外建索引；不复制原件、全历史或逐字段序列。三个hex revision约192字节，三质量约24–42字节，空值位图/变长头/对齐另计，平均增加约240–320字节/行作为待PG校准预算；500会话×实际全市场行数计入S27.10，不能沿用旧行宽不加预算。reason仅错误时有界原因码，单组最多128 UTF-8字节。正常APPEND不重写历史typed行；修订只加实际变更版本。GC/保留沿Canonical保护引用闭包，不新增生命周期，真实表/索引/WAL增长仍须R01实测。

## R00.06 本地诊断与来源只读CLI

`stock-a`控制台入口与`python -m stock_a`共同调用`stock_a.diagnostics.main`。帮助不读取配置；CLI模块导入不读取配置、来源、网络或数据库。支持`doctor`、`source-inspect`、有界只读`source-phase0`、`pg-identity`及显式`pg-bind`。`pg-identity`优先使用`STOCK_A_PG_DSN`安全环境变量；缺失时只从唯一登记的`config/private/postgresql.credentials.json`读取R1凭据，固定目标为`127.0.0.1:5432/stock_a`，秘密只在当前进程内存，不进入输出、日志或子进程参数。

`pg-identity`只运行只读一致性事务，核验真实`session_user=current_user=stock_a`、数据库/schema、数据库与schema归属、必要schema权限、Stock A安装身份、迁移谱系/摘要及账号的集群级权限属性。它不查询服务器日志、表空间、完整关系目录或物理簇控制文件；这些部署管理条件仅由明确的管理员部署核验负责，业务身份CLI不得假称已重新验证。成功状态为`DB_ACCOUNT_READY`与`DB_MIGRATION_READY`，并同时返回`BUSINESS_PIPELINE_PENDING`；身份通过不代表R01/R02业务链实现或验收完成。`pg-bind`仅由真实`stock_a`会话执行已登记前向迁移，不创建数据库/schema、不改写已应用迁移、不触碰V4对象。错误目标须在连接前拒绝，错误类别不输出驱动异常文本。

真实业务连接必须确认为固定库/schema及`stock_a`账号；`stock_a`不是超级用户，不授予CREATEDB、CREATEROLE或BYPASSRLS，并拥有本项目数据库/schema内对象管理和读写权限。检查设连接、语句与锁超时，输出脱敏JSON。普通业务连接Ready只表示数据库账号与迁移身份可用，不代表业务数值、流水线、发布或页面闭环通过。
退出码固定为：0仅表示所请求的本地命令完成（doctor仍固定返回3，因为本地结构诊断不能证明来源或PG运行就绪）；2表示CLI参数或单位/预算合同错误；3表示配置或来源能力不可用；4表示操作系统拒绝访问；5表示工程I/O、流合同或未分类工程错误。稳定读取错误码按固定表映射：`SOURCE_ACCESS_DENIED`映射4；配置/来源缺失、路径/数据无效、预算超限与超时映射3；`SOURCE_IO_ERROR`、`STREAM_CONTRACT_ERROR`、`SCAN_NOT_COMPLETE`及未识别读取码映射5。配置根/最终路径解析和配置打开中的真实`PermissionError`映射4；配置不存在、格式/合同错误映射3。错误JSON保留稳定code、reason_category及可用记录位置，不输出cause文本或敏感路径。配置根或最终文件路径解析、配置文件打开时的真实`PermissionError`映射4；其他配置路径解析/文件读取`OSError`以稳定码`CONFIG_IO_ERROR`映射工程退出5。JSON解码、UTF-8和合同错误仍映射3。来源保护根解析后的`stat`权限失败映射`SOURCE_ACCESS_DENIED/PERMISSION`及退出4，其他`OSError`映射`SOURCE_IO_ERROR/IO`及退出5；缺失、非目录、越界仍按路径不可用映射3。JSON错误对象保留`cause_type`，不输出底层异常文本。`doctor`有可读结构时输出`LOCAL_DIAGNOSTIC_ONLY`并以3退出，分别列示来源根声明、包/版本/DEV或INSTALLED身份、配置/工作根、数据库及应用声明和未连接/未验证状态，`business_start_permitted`恒为false。无配置、坏合同、缺少所消费键、错误类型或路径策略不符写中文错误JSON并以3退出。参数解析错误写中文错误JSON并以2退出。

DEV与INSTALLED共用唯一固定槽位`G:/codex work/Stock A/config/runtime.defaults.json`，不按cwd、安装目录、环境变量或命令参数改变配置根；显式`--config`只接受该唯一文件。只读取登记的runtime.defaults，不递归发现其它文件。配置根/最终文件路径须在唯一config槽位内；违反时拒绝且不创建配置。窄校验覆盖本命令消费的workspace/config路径、只读TDX根策略、STOCK_A项目与合法UUID、未部署时的实例/簇占位、固定`stock_a`库/schema、服务角色声明，以及已登记启动安全布尔值的精确类型和值。未部署状态只接受`BIND_DURING_EXPLICIT_ENABLEMENT`占位，不把占位当实际身份；已部署声明须有合法实例UUID及正十进制簇标识。INSTALLED模式还要求当前模块文件属于已安装的stock-a发行包。doctor不探测来源字节、PG/端口或启动进程，也不把结构诊断称为来源或数据库就绪。总帮助和三个子帮助使用中文usage、分组标题和帮助说明，命令/参数标识保持稳定。导入探针须在干净子进程真实导入前安装对配置/来源文件、网络和数据库模块的禁止访问监视。

`source-inspect`仅处理一个绝对路径日线文件。来源保护根仅来自已验证配置；根为空则在打开文件前以`SOURCE_NOT_CONFIGURED`拒绝。单位版本、金额倍率、数量倍率和读取预算由调用方显式提供，构造既有`UnitContract`与`ReadLimits`；底层只调用`open_day_file`，扫描至EOF并取得完整summary后输出原始字节SHA、记录数、首尾日期、分组质量、只读句柄身份、预算及含时区的本机读取起止时间。该时间不代表来源可用/捕获/封口或交易所时钟。错误复用`DayReadError`稳定代码与位置，不输出部分结果。路径只作定位，不产生证券身份或PIT声明。

研究查询从`runtime.defaults.json`中的TDX只读来源根定位日线文件，按显式单位合同与预算完成整文件扫描，再复用既有Core。年度日历资源由包内`cn_equity_sessions_YYYY.json`按年份动态装载；每个资源必须有完整年度覆盖、可追溯HTTPS来源、经核验状态、严格递增且不重复的会话，并与列出的官方休市区间逐日闭合。当前2025、2026年资源已按沪深交易所年度公告交叉核验；加载计算历史时只取截至目标年的连续年度后缀，并单独报告已知资源跨度内缺失的中间年度，不能将间隔两侧会话拼接为连续历史。目标日不在目标年度会话集合时拒绝查询。若当前年度截至目标日少于70个已知会话且前一年度资源缺失，原始目标日行情仍独立返回；仅依赖不足窗口的Core字段标记`UNKNOWN_DATA/CALENDAR_LOOKBACK_NOT_COVERED`，不把完整查询整体拒绝。跨年连续年度资源可正常组成Core历史；缺bar的正式会话保留为`UNKNOWN`，不会推断停牌/上市前；在已覆盖年度扫描到休市日记录则拒绝该来源。

来源代码仅是研究序列定位键，不提供稳定`security_id`证明。输出区分来源文件最新记录`source_last_session`、研究目标`target_session`和本机只读扫描`read_time`；金额/数量字段的编码质量与单位可信度分开，倍率始终标为调用方假设。核心计算继续使用既有`calculate_core`，并输出原始未复权价格坐标。`research-stock`和`research-compare`复用同一Core生成有限盘后基础观察字段（原始收盘、MA5/20/60、ATR20、ret5/20、金额/数量及均线相对位置），逐字段保留质量和原因，整体标记`RESEARCH_PREVIEW_NON_PIT`。单股命令可选`--include-profile-preview`，在同一次真实Raw/Core读取上读取固定day-chain合同，并调用既有`evaluate_profile_kernel`评估满足实际输入依赖的规则；局部适配只把同目标日`raw.close`作为RAW坐标预览输入，不调用正式P06复权生产者。每个规则输入携带生产者源码摘要、原始文件摘要、窗口端点/摘要、质量、单位和坐标；本机扫描时间不作为历史可得时钟。周/月闭合周期输入未从日线入口接通，全市场RPS/相对市场指标缺少端点完整Universe或指数序列，逐项标记`NOT_IMPLEMENTED`/`CONTRACT_UNBOUND`。`profile()`继续因可信FOUNDATION选择器缺失而阻断；本预览不生成正式Profile、Seed、Priority、评分、排序或交易信号。`research-compare`每批最多20个不同证券，在每只证券原有读取预算之上共享`max_total_bytes`、`max_total_records`和`max_total_seconds`；耗尽后保留完整请求分母，为剩余项目输出`NOT_EVALUATED`及原因，并校验`available`、`failed`、`partial_unknown`、`not_evaluated`分区之和等于请求数。耗时预算在每个读取块和证券边界检查；同步文件系统调用不能在执行中被强制中止。查询始终标记`NON_PIT_RETROSPECTIVE`；不连接PostgreSQL、不写数据库或持久业务文件，也不代表来源PIT、身份或公司行为已验证。

`research-stock`在上述单次完整TDX只读扫描后复用`build_tdx_capture_envelope`，并由纯选择函数生成仅限本次调用的Canonical行及目标字段；既有`calculate_core`直接消费这些带字段质量的会话行，JSON和中文摘要披露目标日、原始字节SHA、实际本机读取时钟、调用方金额/数量倍率、来源代码身份层级、缺bar的UNKNOWN语义及未满足的PIT/准入条件。选择封套不签发稳定security_id、官方成员/上市状态、available_at、FOUNDATION、持久接受或正式生产准入；来源行只选目标会话及之前，后续来源行计数并排除。缺稳定实体身份时Canonical field/window digest保持未生成，不能用来源代码伪造业务身份。

`research-stock`逐对象新增`raw_availability`和`core_availability`，分别给出可见/未知字段数量与原因；原有`status`保持兼容且说明其判定范围。`research-compare`保持原`status`、`classification`和分母，增加Raw/Core独立汇总；`COMPLETE_WITH_DISCLOSURES`只表示请求对象已处理并附带披露，不表示所有指标已知。

`research-universe-preview`从已配置TDX根内动态枚举`vipdoc/sh/lday`、`vipdoc/sz/lday`，按`.day`文件名归一来源代码并复用现役沪深主板/创业板范围函数；保留ST候选但不从文件名推断ST事实。候选契约为`TDX_SOURCE_CANDIDATES_NON_PIT`，不认证稳定证券身份、上市或当日可交易状态。每个目录项必须在只读保护根内；目录缺失、路径越界、重复代码、读取中目录变化或发现预算耗尽时明确拒绝完整分母。目录发现有累计项目/耗时预算，超预算返回`discovery_complete=false`和已见计数，不输出完整候选总数。标准化代码字典序稳定分页，默认20、最大100，支持offset/limit及市场、板别过滤；输出同时列总候选分母、过滤分母、本页、页后剩余与未评价分母。

每页只查询页内对象并继续复用`research-stock`/`research-compare`和唯一`calculate_core`。超过20只时按20只子批调用既有比较入口，但外层按已消耗字节、记录和总耗时递减同一`CompareBudget`；预算耗尽后保留当前页剩余对象为`NOT_EVALUATED`，并按过滤候选全集披露未评价数。完整JSON保留每对象Core字段、Raw/Core独立可用性和未知原因；默认CLI短摘要显示代码、市场/板别、来源末日、Raw收盘、MA20、ATR20、ret20、Raw/Core状态及原因，`--format json`可读逐字段详情。生成的单股详情命令带有相同目标日、单位与单文件预算，并附加`--include-profile-preview`；候选列表本身不为展示组件摘要扫描全市场。目录候选与基础观察均是NON_PIT、原始未复权研究预览，不进入正式Profile选择器，不生成Seed/Priority/策略结论，不连接PG或写TDX/业务持久状态。

`research-universe-preview --include-profile-preview`在调用端只装载一次固定day-chain合同，并将其沿当前页20只子批传入既有`research_compare`与`research_stock`；8个当前可执行规则直接消费同一次TDX→Raw/Core结果，2个闭合周期规则仍为`NOT_IMPLEMENTED`，相对市场规则仍为`CONTRACT_UNBOUND`。画像计算包含在外层单页共享耗时预算内；超时结果转为`FAILED`或剩余请求保留为`NOT_EVALUATED`，不得带旧画像或视作已评价。带开关的JSON在已处理对象内输出完整11项组件及逐项质量、缺因、规则/输入来源，`summary`提供紧凑组件状态，`profile_preview_denominators`按本页实际返回画像的对象汇总组件`evaluated/observed/unknown_data/not_implemented/contract_unbound`；FAILED和NOT_EVALUATED不生成组件。默认无开关时保留原查询结构与摘要行为。中文摘要逐对象展示8项规则的值或`UNKNOWN_DATA`原因及3项未接能力原因。以上仍仅为来源候选页RAW_UNADJUSTED/NON_PIT预览；不扩大为官方证券总体、正式PIT、全市场Profile、RPS、PG/API/UI或日更发布，不开放生产`profile()`。

`source-phase0`仅对配置内唯一显式绑定的本地TDX根工作。动态、有上限地枚举`vipdoc/{sh,sz,bj}/lday`目录，按字典序从每个市场目录选一个文件并经`open_day_file`完整只读扫描；样本单位固定标记`TDX_RAW_DIAGNOSTIC_ONLY`，不得消费其规范数值。按显式文件/总字节、记录、目录项和耗时预算核验实际字节与摘要；超限、权限拒绝、路径逃逸、读取中变化或不完整扫描均不生成成功摘要。通过`read_protected_bytes`只读获取GBBQ时同样验证根内最终句柄、身份、版本、EOF及预算，再复用`decode_gbbq_bytes`解析。能力记录区分FULL_PASS/DEGRADED_PASS/BLOCKED/UNAVAILABLE与required、样本分母、单位/权威、双时间、消费者准入。阶段0输出只回给调用方，不写文件或数据库；BLOCKED必需能力以退出码3结束并禁止相应消费者。文件路径/mtime只用于定位和本地观察，不证明发布时钟、官方身份、交易日历、上市状态、PIT或封口。

## 通达信官网ZIP全范围目标日与Foundation输入生产者

已本地重验SHA-256/CRC的VIPDATA ZIP可作为动态来源候选池，并按稳定顺序逐页评价沪深主板、创业板目标会话。每条候选必须落入`TARGET_PRESENT`、`TARGET_MISSING`、`READ_FAILED`或`NOT_EVALUATED`之一；有目标bar时单列价格、金额、数量质量及原因。每行绑定包SHA/CRC、ZIP条目路径和目标日；完整读取行再绑定条目SHA、日期范围、读取起止时钟/角色和实际预算消耗。未完整读取、读取失败或零字节占位的entry SHA/读取时钟保持空值并保留状态原因，不得伪造完成时间。候选分母只表示ZIP中的来源代码文件名，不表示全部有效上市股票。总分母、评价状态分区和每个字段质量分母必须闭合；预算耗尽保留未评价尾部，读取错误保留稳定原因。

单证券/有限页研究生产者可从同一已验证ZIP句柄直接流式读取条目，不创建临时业务文件。条目扫描构造包含包身份、条目摘要及本机观测时钟的`TdxCaptureEnvelope`，由现有Canonical选择器验证后交给现有`calculate_core`；目标日之后的行不进入Canonical/Core。包/条目SHA及捕获时间是provenance，不单独改变字段组语义revision。真实样本技术指标使用独立Oracle复算。

来源代码仍只构成source symbol。包发布日期、available_at、严格PIT、稳定security_id、正式成员/上市状态及成交金额/数量单位权威未建立时，仍禁止生成正式Canonical持久行及Foundation正式发布；此状态不抹掉可核验OHLC。全范围候选核验不创建或写入数据库、不替代PG持久化及读回验收。北交所为optional；本地安装构建依赖与符号链接权限限制单独报告，不阻塞主线。
