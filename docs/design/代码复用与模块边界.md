# 代码复用与模块边界

合同：STOCK-A-CODE-REUSE/R4。此文说明新项目中如何复用计算内核、保留单一实现并按真实消费者划分模块。算法数学语义见 [算法合同与升级规则](算法合同与升级规则.md)，现行数据路径见 [实现详细设计](实现详细设计.md)。

## 1. 复用和删除原则

优先复用经逐函数核实的解析器、数值内核、状态谓词和页面交互。复用前确认输入/单位/窗口/时间角色、缺值处理及独立正常和边界结果。只更改职责边界，不因架构简化而改写已确认金融公式。

源码在src/stock_a内按实际职责保持单实现：application编排CLI/API用例，storage/postgres访问PG，service承载HTTP接口，canonical承载可复用规范事实转换，research承载研究算法，contracts只加载运行时真正消费的字段语义。页面资源独立位于web/。

复用模块须有现役CLI/API/PG/UI消费者，或属于明确采用且即将接线的单一领域规则。每域仅保留一套生产实现。用户可见的算法状态事件和持续跟踪属于研究业务，按业务键及规则证据保留。

## 2. 当前模块和真实消费者

| 模块 | 现行职责 | 真实消费者 |
|---|---|---|
| application | 解析参数、组装来源或PG研究请求 | stock-a、python -m stock_a、API请求 |
| sources | 只读解析本次指定来源 | Raw事实导入 |
| canonical | 日期、价格坐标和规范输入处理 | Core、周期、画像及研究计算 |
| research | 价格画像、D0/D1、市场和板块分析 | 单股、市场、板块研究 |
| storage/postgres | 精确业务键的Raw、Profile、成员数据读写 | CLI/API和预览服务 |
| contracts | 校验来源/Core/Profile字段公式、单位、窗口与质量 | Core/Profile合同调用点 |
| service/web | HTTP数据接口、页面与静态资源 | 本机开发研究预览 |

任何保留的PG列都须说明具体表键或外键消费者。现役业务表使用单列BIGINT IDENTITY主键与必要的短自然业务唯一键；来源包ID、捕获ID和Profile显式修订仅在有真实消费者的事实关系中使用。TDX原包SHA仅在入口校验记录，不进入Raw/Core/Profile/Seed/D0/D1/市场/板块/PULSE/Cohort/Forward、CLI/API、页面或缓存。DEV/PROD/TEST namespace不作为业务行身份。

## 3. 复用动作

1. 确认旧/新函数各自输入和直接调用点，定位独立预期。
2. 保留计算函数及数学边界，删除不需要的文件IO、网页、PG控制或旧路径副作用。
3. 由唯一application或storage适配器传入明确日期、价格坐标、来源版本和质量字段。
4. 用错误旧例、正常例和边界例逐值验证。数值差异需明确对应新合同的语义变化。
5. 检查CLI/API静态资源路径和所有真实调用点；无消费者实现即删除。
6. 将测试和独立Oracle留在G盘外部测试根。仅业务代码、正式文档、配置和迁移进入Git白名单。

## 4. 模块退出条件

兼容函数只为当前一个调用者保留，并在调用处切换后移除。不得在根包内长期保留平行Reader/Builder/Repository。正式代码不得导入测试脚本、阶段产物、外部临时工具或旧项目。
