# 代码复用与模块边界

合同：`STOCK-A-CODE-REUSE/R3`。本设计规定旧V4业务代码如何成为Stock A的实现材料，配合[主规格](../../PROJECT_SPEC.md)、[产品需求](../requirements/产品需求.md)、[算法合同](算法合同与升级规则.md)、[实现详细设计](实现详细设计.md)和[完整业务链](数据业务完整闭环.md)使用。具体旧提交、文件SHA、符号行号、移植进度与执行结果存外部交付目录，不在本文件记阶段回执。

## 1. 复用原则与裁定

以正确且可验证的现有代码为默认起点。复用目标是保留解析、数值、状态与产品交互的有效工作；新项目重新整理依赖、存储与发布边界。旧仓只读，不通过修改旧文件给新项目供能力，不以新包直接导入旧仓。

| 类别 | 处理 | 判定条件 |
|---|---|---|
| A 保留内核 | 抽取已有函数/小模块，主要修改包路径、注入参数及中文错误文案 | 算法语义符合现行合同；依赖可闭合；正常/边界/已知故障向量通过 |
| B 改造后复用 | 保留正确计算段，修复字段/单位/窗口/前态/身份/副作用 | 差异在合同中可解释，并有错误旧例及独立预期；不能只换函数名 |
| C 替换连接与持久层 | 复用业务经验及无副作用小工具，重写有问题的编排/数据库/读取部分 | 原实现会引入动态schema、多权威、重复payload、脚本或旧文件依赖 |
| D 不进入当前产品 | 保留旧仓只读参考 | 新闻、历史任务脚本、测试/快照/包/数据库、退役入口和未采用能力 |

A/B表示移植策略，不是已经通过新项目验收。旧代码数值通过只在其原输入/坐标/时间/范围内成立；每个实际移入单元仍要绑定新合同和外部回归。代码复用率按移入符号/语义和新增改造分别记录，不用复制行数设指标，更不承诺未经盘点的百分比。

同一计算语义尽量保留原函数体，不为统一风格重写。若必须改公式、失效线、资格规则或排序，登记算法版本和差异；单纯包路径/参数注入调整不改变算法语义身份。新项目Pure Core板块资格、D0四场景和D2失效等新选择与原数学内核分别管理；新规则未采用时，不影响TDX解码、精确复权、合法Core等独立工作的移植。

## 2. 目标包与依赖方向

唯一Python业务包采用`src/stock_a/`，按实际引入创建下列职责模块，不一次铺空目录/空类。前端优先使用已有产品ES模块/图表交互，经清理后归`web/`，不因为新建项目更换整套前端框架。

| 目标职责 | 内容 | 允许依赖 |
|---|---|---|
| contracts、domain | 输入/输出类型、质量、窗口、坐标、业务键、合同参数 | 标准库及明确业务数学依赖 |
| sources | TDX解析/捕获、Bao补充、来源能力和内容存储 | domain、contracts；通过端口接口登记捕获 |
| canonical | 身份/日历/成员/制度、RAW/调整/周期 | domain、contracts；消费明确来源事实 |
| factors | Core、横截面、独立D0原语 | 规范输入；不访问DB、HTTP、旧文件或页面 |
| research | Profile/Seed/Sector/LOO/Rotation/Market/D0/D1/D2/Risk/Priority | 显式字段/前态；不得同日反向依赖 |
| tracking | Focus/Cohort/T0/Forward纯计算与业务调度规则 | 已冻结研究结果、日历和后继接受来源 |
| storage | 唯一PG连接、typed repositories、版本/事务/迁移 | domain/合同；不执行领域算法 |
| publication | Owner seal、Manifest/Index/Head、outbox与读水位 | storage端口及明确候选；不另建schema |
| application | DayPlan、DAG执行、恢复、单writer/任务锁、唯一CLI | 上述端口/领域；无旧任务脚本和旧入口依赖 |
| service、desktop | 只读查询/显式写命令、轻量HTTP、托盘/安全退出 | application接口和只读repositories |

迁移期间允许以新类型包住已抽取内核，适配器必须处于唯一边界且有删除条件；禁止`sys.path`插入旧仓、跨仓软链接、动态加载旧源码、FunctionType替换全局或长期保留两套同义实现。新包从干净子进程安装/调用也必须工作。

## 4. 实际抽取的标准动作

1. 选择U单元和旧提交/文件/符号范围，从只读源码取出；外部记录原SHA/直接依赖。读取旧测试只是继承反例，不自动执行旧fixture或恢复入口。
2. 保留选定函数与必需类型，展开最小直接依赖；业务算法只接受规范类型、参数及冻结前态。需要的共享数学工具只有一个现行实现，不沿着旧import链整包搬入。
3. 在新包内改导入和错误文案，移除旧路径、脚本、候选字面量、全局参数读盘、隐式联网/写库；source/storage/application承担实际IO，配置只从新项目config登记目录加载；来源经规范化入PG；每日结果与恢复游标只写必要PG字段，不保留文件承载例外。
4. 先运行外部纯回归：正常、边界、已知故障和独立预期。合同未改的输入逐值/质量对齐；合同改变的输入明确列旧/新差异和理由，不强求继续复制旧错误。
5. 检查新包实际import闭包及证券/板块/日期字面量；所有业务入口从动态上下文读取市场和日期。协议布局常量、制度数据与参数另行分类，不全局删除数字。
6. 接入DayPlan实际字段生产者与消费者；该单元从纯测试走到typed PG、Owner/索引、实际API/UI及恢复验证。存储/业务/服务结论分别记录，最后只提交白名单业务和正式规范。

## 5. 旧代码携入的禁止项

禁止把旧schema、数据库目录、行情包/快照、候选Owner/ReadIndex/Head、PIT首冻、运行包、scripts/测试树、审计报告、阶段任务/回执、config备份、缓存和凭据随代码搬入。需要初始化行情时从明确来源重新捕获并按新键登记，不复制旧PG数据。

禁止长期运行旧代码产生文件，再由新项目读取这些文件冒充已经移植；不得让旧服务成为新API的隐藏后端。旧服务可在受控、只读核对中作为限定参考，正式消费仍必须由新包生成的精确Owner提供。

新闻/外部事件催化、退役页面及在线热榜不进入本次产品。FEP、分钟和复杂模型等可选能力在主研究链之后独立按合同接入；主链接口预留扩展关系即可，不预铺模型数据库和伪实现。

## 6. 未完全定义的规则怎样处理
