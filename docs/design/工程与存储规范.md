## S05 数据模型、版本键与单schema

业务schema固定`v4`，不按模块/release/date/workspace/test建schema或整套表。以下为逻辑表族，不要求同义重复表；迁移只为本阶段实际写读能力新增对象。

| 表族 | 主要业务键/身份与作用 |
|---|---|
| contracts/parameters/migrations | contract_id/version、参数版本、生效范围、schema版本；源文件与实际采用内容SHA |
| source_contents/captures | 只存content_sha、来源/覆盖、单位/解析版本、捕获时钟和验证摘要；不存原字节、响应体或文件payload |
| securities/aliases/status/calendar | entity_id、symbol有效期、日期/状态revision；日历版本与市场角色 |
| sector_definitions/membership | sector_id/type、member_revision、effective/known时点及成员关系 |
| daily_bars/actions/price_coordinates | entity/date/source_revision、RAW单位、公司行为与目标坐标引用；一日一行，不存整证券长JSON |
| factor/profile/domain_results | entity/date/algorithm+parameter+input版本；可索引业务字段及字段质量，未变结果复用 |
| structure/episodes/state/events | event/anchor/episode稳定ID、前态、冻结参数/坐标与关联；源事实/修订追加 |
| focus/cohorts/observations | 跟踪操作与研究样本分开；观察key含T0/Lane/rule/entity/capture revision |
| schedules/settlements | observation/horizon/due_session；settlement_revision、evaluation/source identity；不让PENDING卡住DUE |
| manifests/heads/jobs/outbox | 不可变版本向量、受控CAS指针、run阶段/失败/幂等及事务outbox |
| serving indexes | 检索键、稳定排序/必要摘要、manifest引用；可再生，详情按需读取 |
| optional model | 实际功能实施时按typed键新增；不先建35张空表，不通用payload承载全部业务 |

PK/UK/FK/CHECK覆盖业务日期、entity、版本/namespace及内容一致性，迁移合并后同kind+fact_key不得覆盖。精确manifest跨表冻结版本向量，逻辑角色唯一；不能因追求一个Head而把来源/模型/结算所有修订压进单指针。

源/已接受历史/首冻/标签/预测事实不可原地改写；修正追加revision，first-observed与latest-validated分别可查。当前指针是受控可变对象，CAS与receipt/outbox同事务；失败全部回滚，历史不删。源locator只作可选溯源信息，不是已接受Owner的读回/恢复依赖；业务引用用PG主键/版本，不存逐日文件定位来维持运行。

Reader/GET无DDL/DML，默认READ ONLY；请求内count/页/settlement一致快照用RR或经证实等价机制。写事务显式目标/范围，开发凭据可统一，生产最小实际权限另验；不输出口令，不绕过访问控制。

## S06 大表、去重、冷热与容量预算

禁止ZIP Base64→Forward JSON、万能kind/payload热库、每release全量历史复制、ReadIndex values+summary+detail+research_objects重复整对象。必要JSON仅存有schema、有消费者和长度上限的小型附加信息，不得包含二进制、完整行集合、长价格序列、完整响应/解释树；关键事实采用明确类型列与关系。

不变事实按内容/业务键复用，运行尝试与结果身份分离；相同输入重跑只追加短run记录，不新增第二套行情/画像/索引。publication引用变化域的新结果及未变域旧结果，兼容性由manifest验证。索引只持久必要查询字段；运行缓存限内存或受控PG暂存，禁止每日日更生成业务文件/本地数据库/磁盘缓存。

容量按行数×字段/索引/TOAST/WAL、初始历史范围、每日增长、重算峰值、备份/恢复及G盘余量规划；原始源/不可再生证据、规范事实、派生、缓存、日志分级。业务历史保留不是无限保留全部中间态；无消费者候选按保留策略退休，实际删除不改审计记录。

正常流水线回执/任务进度/封存信息存PG短记录，不能每日再导出回执文件。控制记录目标≤64KiB，>1MiB报警逐对象核验；详细业务存typed事实并引用，开发取证结果可外置但不是运行依赖。Git禁止任何运行报告/证据/回执/测试/样例数据/快照/行情包，大小不构成豁免；业务必需的无密来源合同可入config或正式设计。测试反例及来源实测证据只在外部保存。物理关系大小/精确或估算行数/逻辑重复/可释放磁盘分开报告，不能将VACUUM FULL代替模型治理。

项目骨架就执行：新release不增加业务schema；GET不写库；同输入幂等无重复大payload；日更持久业务文件数增量为0；PG只新增本日必要行/实际受影响修订及短控制记录，任务结束无临时执行器残留。容量设计必须推演约500个市场会话的事实/索引/TOAST/WAL/候选增长并由实际PG测量校准，不得仅把文件改塞JSON/bytea。后续高级功能不能绕过这些门。

## S16 API、上下文、摘要与错误

bootstrap给context_token、manifest_id、snapshot_date、available_trade_dates和权限摘要；后续query给token/data_date/entity/filter/page。服务端解析/校验全部底层源/成员/坐标/代码/参数/版本，不要求客户端重传整套SHA，也不信自报身份。错误as_of/token拒绝，不fallback最新。

基础context挂Forward读revision、FEP模型/预测和补充source revision；各自变更明确，不跨页漂移。真正服务端分页/筛选/稳定排序，全集无漏重；GET只查现成结果，不做大历史计算/下载/训练/DDL/发布。

稳定业务digest包括值、质量、真实provenance、时间/合同/参数/producer，排除cache_hit/耗时/request_id/临时路径；规范编码拒NaN/Infinity。缓存键覆盖直接/传递源、adapter、参数、token/date/query；合法变化失效，坏SHA不能复用旧结果，缺源失败有界缓存。

原字节SHA与约定LF规范语义SHA分列，不能为换行差异误判内容破坏或放宽真正内容校验。当前repo HEAD与last_loaded_build/实际资源SHA/instance/workspace/PG分别显示；代码push不等服务加载。

value/quality、时间证据、使用权限、工程错误及结算状态正交。已知0/FALSE/NONE、不适用、缺来源、窗口不足、未实现、合同未定、错误、尚未到期分别用中文解释；不能捕获所有异常返回SOURCE_INCOMPLETE。保留完整分母/全部原因，互斥主状态用于统计。

### S27.1 每日生成什么，存在哪里

| Focus/Cohort/T0/Forward | PG必要冻结特征/成员、观察、期限、结算和质量行 | T0文件、长路径数组/源ZIP进payload、将文件字节存bytea/large object |
| Owner/Manifest/ReadIndex/Head/outbox/回执 | PG角色引用、摘要、计数、瘦索引、受控指针和短记录 | Owner目录、Head文件、封存包、逐日回执和完整API响应文件 |
| DayPlan/进度/恢复检查点 | PG jobs及有界阶段/批次游标、输入digest、已提交范围 | checkpoint文件、磁盘状态数据库、用某轮报告PASS作为恢复/放行依据 |

“关键信息”包含正常计算、历史读回与状态延续必需的规范事实，不能只存SHA/汇总数字而丢失OHLCV、公司行为、成员等必要输入；也不能以完整追溯为名长期保存所有中间值和全量对象。每字段/索引需有消费者、业务键和保留/重建策略；同输入重跑复用，算法/来源修订仅新增真实受影响范围。PG不存源文件、文件镜像、Base64、压缩包、完整二进制或万能JSON；PG自己的数据/WAL物理文件由PG管理，不属于应用生成的业务侧文件。

### S27.2 日更唯一接线与恢复

```text
config内已登记业务配置 + 当日真实来源
  → 流式解析/规范验证
  → PG必要规范事实与来源元数据
  → 领域计算（规范输入；中间态在内存或受控PG暂存）
  → PG领域结果/Owner seal/瘦ReadIndex
  → PG CAS + 短receipt + outbox
  → PG观察/到期结算与恢复游标
  → 同context API/页面
```

禁止“每日业务文件→登记locator→Reader继续打开文件”的旁路，禁止在config写入当日Universe、日期任务卡、日更结果或恢复状态。候选分块写固定PG表，未seal对普通读者不可见；同事务更新已提交批次/输入游标，重试按业务键幂等，不保存整块数据为检查点。数据库事务/游标足以恢复；任何流程若仍需本地JSON/Parquet/SQLite才能恢复，视为实现不合格。

已入库的历史查询、状态前态、到期结算和已接收任务恢复必须独立于临时目录、报告和源包副本。新一日采集仍需当日真实来源，缺新源只影响该日更新，不得破坏已接受历史或回退其他日期。原始TDX根保持只读，不删除用户原始文件。

### S27.3 文件引用的允许范围

| 文件角色 | 允许范围与限制 |
|---|---|
| 业务配置/合同/参数 | 文件唯一根为G:/codex work/Stock A/config，逐文件登记角色/schema/消费者，按允许键加载；禁止外部根、未知文件递归加载、链接绕出根、旧项目或安装包配置fallback。配置修改属明确配置操作，日更任务无配置写权限 |
| 私密配置（如需文件） | 仅config/private且不入Git；或由系统安全存储/秘密环境变量注入。环境变量/命令行不能指定根外配置文件；不复制秘密进日志、digest或过程报告 |
| 程序/静态资源 | 当前业务包/声明依赖及随包静态资源；不得夹带业务配置、测试、逐日数据或旧仓动态脚本。可选模型只能作为明确模型发布任务的可信部署制品，不能由每日日更生成模型文件 |
| 原始输入/下载 | TDX只读输入和有界临时来源下载可读取；来源校验和规范事实入PG后，源包副本不再是已入库业务的查询/恢复依赖。默认不额外生成逐日原始页/源快照，Bao响应流式/内存解析；原件保留遵守独立来源合同，不拷入PG二进制 |
| 日志/开发取证/显式导出或备份 | 分别按预算、明确开发/用户任务保存，非默认日更业务输出；产品不读取其内容恢复业务。导出/备份不成为第二权威，不默认每日生成全量业务包 |
| 测试代码/脚本/配置/fixture/Oracle/测试文档及结果 | 仅外部测试根或交付过程目录；不得放config、src、resources或正式docs内，不得由正式业务加载。测试可以只读验证正式配置，测试覆盖值只能在外部测试环境提供 |

### S27.4 配置与文档如何保持可区分

唯一公共配置目录登记在config/runtime.defaults.json的configuration_policy中；目前只登记runtime.defaults.json与contracts/day-chain.contract.json。新增业务配置须同时声明角色/schema/真实消费者及Git准入，禁止扫描目录自动收编；测试配置即使改名为production/default也不得准入。config/private只允许私密键，不能作为未登记业务配置、测试参数或日更数据的藏身处。所有应用配置路径解析后必须在上述根内；任何根外配置拒绝，不先加载再裁定。

正式文档只包括根AGENTS/PROJECT_SPEC/README，以及docs/requirements、docs/design、docs/changes内的需求/设计/正式变更；原文件原位更新，不并列轮次副本。规范中的验收条件可以存在；实际测试计划、测试配置说明、阶段测试结论、报告、回执和产物全部外置。目录/文件名检查、配置目录登记及人工用途审查共同执行，不能仅凭扩展名判断；Git准入不等于运行权限，运行时仍须校验配置来源与用途。

### S27.5 必须实现的验证

R00建立config唯一根、逐文件目录与配置注入、纯算法无文件IO；R01采用来源流式规范化；R02落实全部必要PG事实/控制状态和无文件恢复。不得因旧R01只做文件准备而继续堆业务文件：真实PG启用前只能做内存/纯函数验证，不把文件落盘当临时架构。

实际验收必须覆盖：日更持久业务文件写入数为0；清空隔离测试临时区/移走测试与过程材料后，已入库历史查询、前态/恢复和到期结算保持；错日/错Owner/坏摘要/未seal拒绝；根外配置、链接逃逸、未知配置、测试配置/文档混入均拒绝；重复日更无重复大payload。约500会话容量推演须包含正常新事实、实际修订、索引/TOAST/WAL及候选回收，不能把全部原始/中间二进制换成PG大对象。PG内部文件、必要原始输入和有界非业务日志按角色单列，不算业务侧文件豁免。删除/故障测试只操作隔离合成对象，不删除用户真实源、旧库或资料。

以上运行时生产者/配置解析/写入审计/PG容量与恢复验证仍须按实施批次完成，文档与机器声明通过不能冒充实际PG/API/UI验收。
