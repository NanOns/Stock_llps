# Stock A 数据业务完整闭环

## 1. 目标与边界

Stock A 为全市场股票研究提供可追溯的价格事实、来源画像和研究结果。目标产品方向保留全市场画像、市场→板块→个股分析、变化识别与持续跟踪；是否可用须按当前实现、数据覆盖和独立验收逐项说明。

来源摘要、捕获时钟、Raw字段质量和价格坐标随来源事实保存。算法状态变化、Focus与用户研究跟踪按各自业务键保存；价格研究直接读取明确日期和来源版本。

## 2. 现有来源到研究读取路径

1. CLI/API 接收明确的业务日期、来源、证券代码和可选范围。
2. 来源读取边界只读读取授权来源。TDX 来源根永久只读；任务截止之外的数据不能进入本次研究输入。
3. 解析、质量检查和价格计算得到带明确单位、日期、代码及来源摘要的类型化记录。不可用字段按既有公式给出质量原因；不以缺值填充或跨来源回退伪造完整度。
4. Raw 来源日线以日期、来源代码、数据集和包SHA写入 PostgreSQL。捕获时间与内容摘要分别记录，以便解释数据实际可用性。
5. Core/Profile 根据请求的目标日及必要历史窗口计算。持久化画像按日期、包SHA和画像修订读取；直接 Raw 研究按来源记录和日期读取。
6. CLI、API和页面读取有明确业务键的结果；GET只读，不生成DDL，也不触发来源采集。

单个日期、数据包或证券的失败仅影响依赖它的结果。缺少单位、窗口输入、历史Bars或PIT证据时，按算法合同对对应字段降级或拒绝。

## 3. 数据和真实消费者

| 数据 | 主要字段/身份 | 当前消费者 |
|---|---|---|
| Raw日线 | session_date、source_symbol、OHLC、volume、amount、package_sha256、source_capture_id | 单股日线、D0/D1研究、市场宽度、行业成员与画像计算 |
| 来源采集事实 | source_capture_id、source_content_id、采集时间、来源版本、读取行数 | 解释来源内容及采集时钟 |
| Core画像 | 日期/来源股票/坐标、MA、ATR、收益、位置和字段质量 | 日/周/月研究、价格轨迹、市场与板块画像 |
| Profile画像 | Core依赖、计算版本及质量字段 | Profile详情、两日期关系筛查、变化历史 |
| 行业/概念成员 | 当前有效目录与成员日期/来源 | 市场→板块→个股聚合、重叠及成员变化 |
| D0/D1事件 | 业务输入日期、来源捕获、事件谓词与规则版本 | 个股变化识别、事件解释与持续跟踪 |

数据库主键、外键和字段以集中迁移及PG核查为准。已存Profile表仍含source_set_id/source_set_revision历史键，普通Raw查询与价格关系筛查按日期、包SHA和Profile修订定位，不要求调用方传入该键。物理移除须先授权并迁移存量画像。

## 4. 时间与数据质量

trade_date描述业务日期；effective_at描述实体或成员事实生效时间；published_at、available_at和captured_at分别按来源合同保留。所有时间注明时区。后验读取不得被称为历史PIT或真实首捕。迟到或成员回溯只能用于明确披露的NON_PIT研究。

缺失Bars、非法OHLC、负量额、单位未知、来源摘要不符、历史窗口不足、重复成员或身份未映射各自带有具体质量状态。它们只使依赖该字段或分母的计算不可用，不得将程序异常吞成“来源不完整”，也不得误报全市场分母完整。

## 5. 研究与产品结果

价格算法以算法合同中的窗口、单位、坐标、边界比较、舍入和缺失质量定义为准。本文件不重述或改写金融公式。无论结果读取Raw、Core还是Profile，都须以同一版本规则解释数值和质量。

全市场画像、市场轴和市场宽度向板块与个股研究提供可计算输入；板块研究按当前实际成员和适用时间范围汇总；个股研究展示具体事实、历史变化、状态原因和所处板块。成分缺失、身份不确定或历史成员非PIT必须呈现为相应UNKNOWN/NON_PIT，不以当前成员倒填历史。

变化识别比较两个明确日期或前态事件；每个差异追到具体输入与谓词。持续跟踪和Forward若实施，是独立的用户业务结果，有真实T0、后继观测、到期规则及删失原因。价格画像重算不依赖读取水位或发布版本。

## 6. API与页面路径

已有API按页面实际功能提供搜索、时间线、周/月汇总、画像关系筛查和来源变化观察。请求绑定精确日期、可选来源包SHA和必要历史画像键。筛查接口的金额下限和成交量下限按AND同时生效；总数、分页、默认省略参数与非法参数行为按API合同及CUT03验收。

页面只呈现API实际返回内容。用户进行日期切换、代码搜索、分页和展开/折叠时，结果应与输入日期和实际PG数据一致。不存在的API或静态占位面板不得显示为已完成能力。

## 7. 范围、恢复与安全

数据导入以业务唯一键幂等写入，并用数据库事务维护单次写入的原子性。来源事实与派生画像分别使用自身业务键；同一输入修订时仅更新受影响日期和真实消费者。并发冲突由唯一约束及事务处理；不额外建设租约、防护代数、全局候选发布或恢复状态机。

GET路径只读。新增或修改表结构必须使用集中迁移并完成中文表/列注释、引用检查和有界数据转换方案。PG物理DROP、TRUNCATE、DELETE或破坏性ALTER依具体对象另行授权，文档或代码改写不代表已执行物理清理。

来源根保持只读；截止日期按当前任务明确值执行。正式数据库仍为127.0.0.1:5432/stock_a.stock；生产服务与生产数据状态不属于开发服务操作范围。

## 8. 完成判定

每项能力分别记录公式数值、输入范围和质量、PG读写、CLI/API行为、浏览器可见结果及仍未实现的消费者。局部画像成功不等于市场、板块、个股和持续跟踪全部完成。真实数据缺失、未来尚未成熟和当前实现未接通必须分别说明。测试过程与结果保存在外部交付目录，不进入Git。
