# Stock A 数据业务完整闭环

## 1. 目标与边界

Stock A 为全市场股票研究提供可追溯的价格事实、来源画像和研究结果。目标产品方向保留全市场画像、市场→板块→个股分析、变化识别与持续跟踪；是否可用须按当前实现、数据覆盖和独立验收逐项说明。

BaoStock查询捕获ID、实际捕获时钟、Raw字段质量和价格坐标随来源事实保存；TDX行业/GN成员使用各自快照身份，不能作为股票价格捕获。已实现的算法状态变化按业务键保存；正式跨日Focus与用户研究跟踪按实际实现和证据区分；价格研究直接读取明确日期和来源版本。

## 2. 现有来源到研究读取路径

1. CLI/API 接收明确的业务日期、来源、证券代码和可选范围。
2. 来源读取边界只读读取授权来源。TDX 来源根永久只读；任务截止之外的数据不能进入本次研究输入。
3. 解析、质量检查和价格计算得到带明确单位、日期、代码、来源版本及捕获引用的类型化记录。不可用字段按既有公式给出质量原因；不以缺值填充或跨来源回退伪造完整度。
4. BaoStock股票日线以日期、来源代码、adjustflag/价格坐标、单位、字段质量和真实查询捕获写入PostgreSQL；未复权`adjustflag=3`和前复权`adjustflag=2`是独立价格坐标。TDX只保存行业/GN目录和成员快照，不再提供股票Raw价格或回退。捕获时间、来源修订和字段质量以typed事实保存，解释数据实际可用性。
5. 股票价格读取只使用BaoStock已存捕获：RAW未复权用于真实当日价格、涨跌停参考和量额/换手，QFQ前复权用于跨日连续结构与周月价格结构，并明确后验`NON_PIT`。TDX仅提供行业/GN目录及成员关系；本地TDX根继续只读，不进入普通价格路径。数据任务不因配置而自动采集来源，来源读取仍须由显式获准操作发起，并受任务截止日、会话预算和字段合同约束；失败按来源及其真实依赖范围标记，不跨源拼接价格或补齐缺值。
6. Core/Profile 使用现役生产者按日期、来源和真实历史窗口计算，已持久化画像按业务键读取。对已经具备真实消费者的全市场、跨日静态研究结果，离线初始化/日更生产者将计算结果写入typed PG业务表；后续日更复用同一生产者。
7. CLI、API和页面按日期、精确来源、算法语义及实际窗口读取完整PG结果。HTTP GET只读，不生成DDL、不采集来源、不触发全市场历史重算；单股下钻、轻量SQL筛选/聚合和小范围比较可即时执行。

现有“数据初始化”和“数据日更”菜单按基础来源、基础画像/指标、研究算法选择现役模块。初始化默认复用Raw，也提供经二次确认的全部业务事实清理重建；Raw目标默认200个官方会话，可改动态N，Core/Profile历史输入窗口单独配置，现役画像和算法输出默认最近5个官方会话并逐模块配置。清理预览按实际Stock A业务表、行数、外键和保留系统对象列出范围；只有Raw来源包与行业/GN成员来源均在删除前核验可重建后才执行。清理事务通过显式列举全部业务事实表的`TRUNCATE TABLE`（不带`CASCADE`）原子清空，不包括安装身份、迁移账本、数据库/schema结构或账号；通过事务级TEMP保留当前重置任务及进度，再在同一事务写入逐表`CLEARED`行数。后续中断沿已提交来源/算法步骤恢复，不再次清空。普通局部清理覆盖已接通模块并核对非外键SQL消费者；混合捕获或未闭合下游时阻断并返回实际依赖范围。初始化与手动日更复用同一来源与计算生产链。

手动日更提供`FULL_THREE_LAYERS`与`SOURCE_ONLY`两个预设。`SOURCE_ONLY`只复用/保存BaoStock双坐标价格事实及TDX行业/GN成员事实，不启动Core/Profile、市场宽度/参与或研究层；`FULL_THREE_LAYERS`按真实依赖执行全部已接通模块。BaoStock价格、行业/GN成员和算法各自有提交状态与独立PG读回；某一来源失败不回滚另一独立来源。任务请求键绑定模式、模块、输出/输入窗口与截止日，不把来源捕获/日历修订/算法修订作为同日多版本并存键。

单个日期、数据包或证券的失败仅影响依赖它的结果。缺少单位、窗口输入、历史Bars或PIT证据时，按算法合同对对应字段降级或拒绝。

## 3. 数据和真实消费者

| 数据 | 主要字段/身份 | 当前消费者 |
|---|---|---|
| BaoStock双坐标日线 | session_date、source_symbol、price_coordinate、adjustflag、OHLC、volume、amount、source_capture_id | 单股日线、D0/D1研究、市场宽度与画像计算；RAW与QFQ按消费者分开读取，禁止TDX股票价回退 |
| 公司行为公告与自研仿射价格链（已退役） | 历史资料曾记录事件引用、源/目标会话与坐标、事件修订及alpha/beta | 无现役采集、生产表或Reader；不解析公告、不生成仿射价格，也不作为BaoStock缺值回退 |
| 来源采集事实 | source_capture_id、provider、价格坐标、目标日期、查询捕获时间、请求/解析合同、读取行数 | 解释BaoStock真实查询范围与采集时钟；TDX目录/成员使用各自快照身份 |
| Core画像 | 日期/来源股票/坐标、MA、ATR、收益、位置和字段质量 | 日/周/月研究、价格轨迹、市场与板块画像 |
| Profile画像 | Core依赖、输入窗口元数据及质量字段 | Profile详情、两日期关系筛查、变化历史 |
| D0单日事实 | 前后态三值、转移、具名原因及来源追溯元数据 | 来源启动变化、D0 API/股票详情 |
| D1逐股结构事实 | 五类生成状态、Raw质量、锚分类计数/分母、窗口与坐标 | 市场/板块D1分布及单股五类状态 |
| D1材料/质量锚 | 锚出生/前后观测、类型、精确坐标、材料变化原因、支撑/缺口质量字段 | 结构类别与原因筛选、单股锚解释 |
| 行业/概念成员 | 来源目录、快照及成员日期/来源 | 行业/GN目录、双板比较、板内RPS与成员下钻；当前快照回看为NON_PIT |
| 板块PULSE与后继 | `source_sector_cross_period_pulse_facts`、相邻transition、followup及cohort typed事实（按业务日期/板块/期限唯一，来源捕获与快照作溯源元数据） | 现有板块目录/历史/详情Reader及Focus板内解释；页面GET仅读取保存结果 |
| D0/D1事件 | 业务输入日期、事件类型与谓词 | 个股变化识别及当日来源观察；不等于完整跨日跟踪 |

数据库主键、外键和字段以集中迁移及PG核查为准。画像、Seed、D0/D1、市场、板块和后继事实用BIGINT IDENTITY父子ID、业务日期与业务对象定位；不保存或传递namespace_id、多版本组合键和下游SHA。DEV/PROD/TEST数据库命名空间隔离不适用于本项目的单库单schema。Codex依据当前明确任务和真实依赖自主判断必要的物理变更，不逐对象申请批准；变更前核实引用、范围和恢复路径，完成事务及独立读回。

## 4. 时间与数据质量

trade_date描述业务日期；effective_at描述实体或成员事实生效时间；published_at、available_at和captured_at分别按来源合同保留。所有时间注明时区。后验读取不得被称为历史PIT或真实首捕。迟到或成员回溯只能用于明确披露的NON_PIT研究。

缺失Bars、非法OHLC、负量额、单位未知、来源版本/捕获不符、历史窗口不足、重复成员或身份未映射各自带有具体质量状态。它们只使依赖该字段或分母的计算不可用，不得将程序异常吞成“来源不完整”，也不得误报全市场分母完整。

## 5. 研究与产品结果

价格算法以算法合同中的窗口、单位、坐标、边界比较、舍入和缺失质量定义为准。本文件不重述或改写金融公式。无论结果读取Raw、Core还是Profile，都须以同一版本规则解释数值和质量。

全市场画像、市场轴和市场宽度向板块与个股研究提供可计算输入；板块研究按当前实际成员和适用时间范围汇总；个股研究展示具体事实、历史变化、状态原因和所处板块。成分缺失、身份不确定或历史成员非PIT必须呈现为相应UNKNOWN/NON_PIT，不以当前成员倒填历史。

全市场或跨日静态计算已存在真实消费者时，页面请求直接读取其完成PG事实；市场/板块汇总优先由事实表按当前成员快照JOIN后SQL聚合，不复制成员集合或整份响应。D0/D1研究结果为来源级NON_PIT后验事实，保持现役公式、窗口、坐标及UNKNOWN质量语义；具体消费者的接通和物理数据覆盖须独立验证。

变化识别比较两个明确日期或前态事件；每个差异追到具体输入与谓词。持续跟踪和Forward若实施，是独立的用户业务结果，有真实T0、后继观测、到期规则及删失原因。价格画像重算不依赖读取水位或发布版本。

## 6. API与页面路径

已有API按页面实际功能提供市场宽度、完整行业/GN目录、双板对比、板内RPS、任意有数据个股解释、搜索、时间线、周/月汇总和来源变化观察。Focus当日五组对既存D0、Seed、九规则和D1在PG中分类、聚合、分页，按当前页读取证据；没有单独的五组物化事实表，也没有证明正式跨日首次入组。现役来源规则观察段复用既有登记、可比性比较器和三态状态机，由离线事务写入typed逐会话事实，再由只读Reader按日期、BaoStock source_capture_id、规则、状态分页；ENTRY、左截断与REENTRY登记作为段根，DAILY_LANDMARK只作为持续观察事实，不建立新段。此能力使用BaoStock QFQ（adjustflag=2）进行跨日价格比较，并限定SOURCE_SYMBOL_ONLY、NON_PIT_EXPLORATORY，不等同正式D2或Focus Episode。请求绑定精确日期、BaoStock source_capture_id和必要历史画像修订。全市场/跨日静态事实采用PG只读服务与真实分页；`NOT_COMPUTED`、`INCOMPLETE`、`NO_CHANGE`和`UNKNOWN`各自返回。筛查接口的金额下限和成交量下限按AND同时生效；总数、分页、默认省略参数与非法参数行为按实际API合同验收。

页面只呈现API实际返回内容。用户进行日期切换、代码搜索、分页和展开/折叠时，结果应与输入日期和实际PG数据一致。不存在的API或静态占位面板不得显示为已完成能力。

行业与GN概念PULSE只绑定来源类型正确、同一观察时刻且目录/成员可用的双快照，成员回看明确为NON_PIT；PULSE、相邻变化及已到期后继由现有typed表保存并由板块API只读消费。缺快照/缺精确Raw时为NOT_COMPUTED，未来期限为NOT_DUE；任何GET都不触发全池计算或读取截止后的行情。

## 7. 范围、恢复与安全

数据导入以业务唯一键幂等写入，并用数据库事务维护单次写入的原子性。来源事实、Core/Profile和派生研究事实分别使用自身最短业务唯一键；同输入重复运行幂等跳过，输入或参数修订时事务替换当前有效结果并按真实依赖窗口有界清理/重算受影响日期和真实消费者。并发冲突由唯一约束及事务处理；不额外建设租约、防护代数、多版本并存、全局候选发布或恢复状态机。

GET路径只读。新增或修改表结构必须使用集中迁移并完成中文表/列注释、引用检查和有界数据转换方案。Codex依据当前明确任务和真实业务事实自主判断并执行必要的PG操作，不按SQL种类、对象或行数逐项申请批准；涉及既存数据时先核目标键、来源、匹配数和事务恢复路径，再执行并独立读回。文档或代码改写不代表已执行物理清理。

来源根保持只读；截止日期按当前任务明确值执行。正式数据库仍为127.0.0.1:5432/stock_a.stock；生产服务与生产数据状态不属于开发服务操作范围。

## 8. 完成判定

每项能力分别记录公式数值、输入范围和质量、PG读写、CLI/API行为、浏览器可见结果及仍未实现的消费者。全市场静态研究的完整能力至少证明结果生成、typed持久化与PG读取可查；源码或合成回归不能代替真实PG写入/读回。Codex按当前任务自主执行必要PG操作，并通过事务和独立读回证明结果。局部画像成功不等于市场、板块、个股和持续跟踪全部完成。真实数据缺失、未来尚未成熟和当前实现未接通必须分别说明。测试过程与结果保存在外部交付目录，不进入Git。
