# 目录与Git准入设计

本设计落实用户指定的Stock A源码/交付路径，以及“Git只保留业务流程相关代码、需求、设计、明确需求变更”的约束。测试、任务材料和执行证据统一外置。

## 源码目录

| 路径 | 职责 |
|---|---|
| AGENTS.md | 开发与交付约束；禁止执行证据/测试入Git |
| PROJECT_SPEC.md | 业务主规格及稳定S编号索引；按责任域链接正文 |
| README.md | 项目入口与业务使用说明 |
| src/ | 来源S、规范事实C、计算F、发布P、服务V及正式CLI；每域唯一实现 |
| web/ | 产品页面及其源码，不含node_modules、dist或测试 |
| config/ | 唯一正式文件配置根；登记的公共业务配置/合同，私密文件仅private且忽略Git；严禁测试/任务配置、数据与报告 |
| migrations/ | 参数化、持续用途的正式业务迁移，不放测试/一次性任务SQL |
| resources/ | 运行必需UI/产品资源，不放截图、快照、行情或测试样例 |
| docs/requirements/ | 当前正式需求，优先更新现行文件 |
| docs/design/ | 业务/架构设计与规范验收条件 |
| docs/changes/ | 明确需求/设计变化，记录新旧规则与适用范围 |
| 根依赖/锁定/打包清单 | 仅限实际业务必需，白名单见.gitignore |

136项现行需求唯一正文位于docs/requirements/产品需求.md；工程/存储/API/安装/验收规范位于docs/design/工程与存储规范.md。根SPEC保留S编号和跳转，不重复整份正文；AGENTS保留根目录以便会话读取。已撤销六项新闻需求，不复制历史参考来填充规范目录。未实施模块保持空目录或不创建，不加占位源码/空表/.gitkeep。

## Git内容准入

默认拒绝未知路径，只允许白名单目录和扩展名。根.gitignore/.gitattributes/AGENTS/PROJECT_SPEC/README为最小仓库控制文件；业务依赖锁和打包定义属于运行必要组成，不得夹带测试依赖/配置。命名允许不代表用途允许。

测试文件/脚本、任务文档/报告/回执、fixture、样例、运行日志、数据、截图、数据库/原始包、构建产物、安装包、压缩归档、密钥、IDE状态，即使很小也不能提交。禁止将这些内容改名到src/config或正式设计目录蒙混。

.gitignore负责普通add的默认拒绝，本地pre-commit检查完整暂存树，pre-push检查待推送提交与树；本地钩子只存.git/hooks，不提交。配置按当前树的公共配置目录、业务角色与存在性检查，拒绝未登记配置、私密文件入Git和明显fixture/Oracle字段；正式文档同时检查明显测试/阶段报告标题。禁止force-add/no-verify/禁用钩子。内容伪装仍须人工逐文件审查，不能宣称能识别所有伪装产物；运行配置根检查与PG验收另行实现。

业务测试和证据仍必须真实执行、可重复、绑定源码/合同摘要，并在外部留存。Git提交只代表允许内容已版本化，不代表工程/数据/API/UI/发布验收通过。

配置准入采用runtime.defaults.json的configuration_policy声明公共文件、角色/schema与消费者；未知/未登记文件先拒绝，不能因位于config自动收编。测试配置与测试文档只放外部测试/过程目录；正式docs不容纳实际测试计划/报告。配置或文档改名不能改变其用途，提交前仍做内容审查。
