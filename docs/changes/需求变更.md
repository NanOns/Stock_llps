# 正式需求与设计变更

本文件仅记录明确的规范变化，不记录阶段任务、执行报告、测试结果或回执。

## CHG-033：阶段交接使用新对话并禁止重复轮询

执行或返修完成并释放写入租约后，立即新开独立审计对话；审计完成后，无论结论如何，均由新的后继对话承接。PASS由新执行对话推进下一依赖就绪目标，NEEDS_REVISION由新执行对话处理对应返修，BLOCKED由新的协调/报告对话说明真实阻碍并在决策或依赖满足前停止相关范围。任何阶段都不得把协调对话、旧执行对话或旧审计对话改作后继角色。

启动后继后，发送方及协调对话立即结束本轮，不在原对话反复等待、调用`wait_threads`轮询或转述后继进度。只有核验租约释放、工具/子进程停止或交接材料完整性确有必要时，允许一次有界确认；确认仍不足则指出具体缺项并停止该次交接，不得忙等或循环检查。后继对话按交接中的绝对路径自行读取规则、任务与证据。此次规范修订针对协调对话在返修进行期间反复等待并复述状态、没有推进业务且没有切换到新审计对话的流程失效；等待或进度转述不计作执行、审计或交付。本变更不放宽单写者租约、阶段结论、阻塞处理或生产准入。

## CHG-021：正式中文诊断与只读日线检查入口

为R00.06采用唯一Stock A中文CLI入口`stock-a`，并提供等价`python -m stock_a`调用；两者共同调度`stock_a.diagnostics.main`。仅开放`doctor`和单文件TDX日线`source-inspect`。doctor只读唯一登记配置并准确报告声明与未核验状态；不得因本机诊断成功而许可业务启动。来源检查复用既有单位合同、有界扫描和Windows只读句柄接口，来源根只从真实配置读取，空根时拒绝。CLI输出为有界JSON并固定退出码；不新增持久配置、数据库表、后台服务或输出文件。该变更不表示真实来源/PG启用、PIT、完整R00/M0或生产切换通过。

## CHG-022：自动交接使用单写入租约和终结回执

R00–R08授权自动流转继续使用指定执行/审计模型，并按目标串行交接。每个目标使用新执行对话，执行完成后必须新开独立审计对话；同一执行对话只可继续尚未完成的原目标，不得转作审计或下一目标。审计未通过时发布唯一、具体的返修卡并新开执行对话；通过后由协调入口或审计交接启动新的下一目标执行对话。处理前置协调/流程问题的对话在该问题完成后结束，不继续承接业务执行或审计。协调入口一次只授予一个执行/返修写入租约；同一目标最多一个活动审计委派，审计只读源码且仅可写获准的外部审核材料。执行方交接必须提交`WRITE_LEASE=RELEASED`、任务范围、固定HEAD/tree、分支、工作树状态及报告/回执/资产绝对路径。协调入口核实最近一轮已终结、无运行中的工具调用或可变子进程，并以只读Git检查确认身份与材料后，方可启动独立审计。审计方以`AUDIT_HANDOFF=COMPLETE`交付PASS/NEEDS_REVISION/BLOCKED、范围和输出路径；协调入口核实交接终结后，只按结论启动对应返修、下一依赖或停止报告。

线程列表的`active`/`idle`只作状态提示，不得单独阻断自动流转；若终结回执、工具状态和只读身份核验齐全，列表状态滞后不阻止后继启动。若实际生成/写入仍在进行、身份不一致或交付缺失，协调入口只做一次有界确认，仍不能核实则报告阻塞，不忙等或循环轮询。已释放线程不得自行恢复写入，须由协调入口重新授予租约。任务卡每一未关闭项必须精确定位事实或疑问，列明影响、检查前置条件、具体输入/步骤、独立预期、要求证据及关闭判据，禁止空泛或重复要求。审计只读但可质疑任何代码与证据；对每个未解疑问要生成执行方可操作的针对性测试/证据要求及独立预期，不能运行测试、构建、打包或安装的审计方不得以无法亲自运行作为放过问题的理由。交接须带租约ID、角色/模型、范围、根与分支基线、写入边界、必要路径、完成判据和失败停止规则。本规则不扩大任何业务或生产切换授权。

2026-10-26最新授权覆盖R00–R08全部大阶段及每个小任务：执行交付后自动新开独立审计，审计NEEDS_REVISION自动新开对应返修，PASS自动新开下一依赖就绪执行；逐任务重复，各阶段另做完整审计。执行/返修Luna/high，普通审计与返修复审Terra/low（2026-10-27调整），大阶段完整审计Sol/high。发送方停止写入并释放租约后创建后继即结束；后继先单次有界确认前序轮次终结再实质工作。该规则替代旧卡的普通完成后等待用户或禁止启动后继、R08未授权条款；真实依赖/访问拒绝/重大设计未决及生产切换边界保持。

## CHG-023：诊断配置与来源根I/O分类

本地诊断配置路径解析或文件打开中的真实`PermissionError`保持权限拒绝类别及退出码4；其他`OSError`使用稳定错误码`CONFIG_IO_ERROR`及工程退出码5。配置不存在、JSON格式或合同错误仍为配置不可用及退出码3。TDX来源保护根解析后的`stat`权限拒绝映射`SOURCE_ACCESS_DENIED/PERMISSION`及退出码4，其他`OSError`映射`SOURCE_IO_ERROR/IO`及退出码5；缺失、非目录、路径越界等合同/路径错误保持退出码3。错误输出保留错误因果类型，不包含底层异常私密文本或敏感路径。该变更仅统一诊断边界分类，不启用来源、数据库或生产运行。

## CHG-024：文件清理不覆盖原始异常

TDX日线受控文件入口在退出、提前停止或失败时仍关闭已打开句柄。原生HANDLE交给`open_osfhandle`前由边界持有，成功后由descriptor接管；`fdopen`成功后流对象接管descriptor。任何接管前失败都恰好关闭当前所有者的资源一次，Windows `CloseHandle`明确声明`HANDLE`输入和`BOOL`返回。若处理期间已有异常且关闭句柄也失败，保留原始异常为主异常；仅在运行时异常对象提供可调用的`add_note`接口时附加清理失败说明，以兼容项目声明的Python 3.10及更高版本。若无正在传播的原始异常，关闭失败仍按来源I/O错误报告。该行为只保证异常因果与兼容性，不扩大来源读取或生产启用范围。

## CHG-025：增加有界本地来源阶段0命令

增加正式中文CLI命令`source-phase0`，只核验唯一配置根内的本地TDX来源。命令对三类市场的日线目录执行有界动态枚举，按显式样本规则完整读取样本，使用只读句柄确认最终路径及读取期间文件身份；GBBQ使用相同根/句柄/字节预算后复用既有纯解析器。输出真实观测时间、字节SHA、记录/目录覆盖、预算、字段单位与权威缺口、required/optional能力状态及消费者准入，不生成业务文件或数据库事实。诊断样本使用`TDX_RAW_DIAGNOSTIC_ONLY`，不进入规范化消费者。必需能力未成立时退出码3并标记BLOCKED；错误、超限、短读或来源变化不得以部分结果给出成功摘要。配置只绑定经过核验的用户指定根；不自动发现其它磁盘/目录、不联网、不推断身份、PIT或交易日历。该命令不代表PG、M0或生产启用通过。
