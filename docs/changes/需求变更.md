# 正式需求与设计变更

本文件只登记现行设计决策。被取代的历史方案可从Git历史查阅，不作为当前执行规则。产品需求和算法公式分别由产品需求.md、PROJECT_SPEC.md及算法合同与升级规则.md维护。

## CHG-016：保留的金融研究公式与状态语义

继续采用现行算法合同中明确列出的三窗口、RPS中秩、金额比率分母、市场宽度主式、Core/Supplemental隔离、板块与LOO、Rotation、D0/D1/D2、Focus顺序及变化语义。来源单位、坐标、质量、时间角色和未知状态不得被工程改造改写。公式变更须有独立正常、边界和错误向量；本决策不表示其所有消费者已实现或真实数据已验证。

## CHG-055：删除式架构减负

现行数据路径为来源读取→Raw PG→Core/Profile→具体研究消费者→CLI/API/页面。源码、页面和机器合同只保留可追到真实消费者的内容。已应用迁移及账本不改写；未使用控制表与现存画像键的前向清理依据PG真实引用制定。

来源内容摘要、实际捕获时钟、Raw质量、金融算法事件和用户持续跟踪属于业务数据，按真实消费者保留。已存Profile表的source_set_id/source_set_revision仍是当前数据库主外键；价格关系API按日期、包SHA和Profile修订解析行键，不将该键暴露为读取前置。

本决策不撤销136项产品需求，不改变金融数学语义，也不把全市场画像、市场→板块→个股、变化识别或持续跟踪宣称为已全部实现。按实际日期、来源版本和质量逐消费者报告能力。

## CHG-056：静态研究事实先生成并持久化

已有真实消费者的全市场、跨日或历史静态研究结果由离线初始化/日更生产链计算并持久化到有业务键的typed PG事实表；初始化与日更复用同一生产者。服务端默认只读能证明完整的精确日期/来源/算法事实，HTTP不得隐式重算全市场历史。单股下钻、轻量SQL筛选/聚合及小范围比较可即时计算。D0/D1材料在不改现行公式、窗口、坐标和NON_PIT边界的前提下分事实、质量及原因保存。行业/GN当前成员继续使用现有快照JOIN，不复制成员事实。

缺结果、分母不全、零变化和UNKNOWN分别表达；结果生成、typed写入、PG完整读回与真实消费者是分层验收项。必要PG操作的自主判断与执行边界由后续CHG-057统一规定。现役页面应直接读取已完成PG事实并移除HTTP全池重算，不保留双Reader；源码或迁移文件不等于物理应用及消费者验收。

## CHG-057：按业务任务自主判断并执行PG操作

用户决定：Stock A数据库操作由Codex依据当前明确业务任务、真实PG身份与现场数据状态自主判断并执行，无须按SQL种类、表/字段、影响行数或操作类型逐项申请批准。对既存数据的纠错、DDL、DML及必要迁移属于任务范围内操作；执行前核对业务键、来源与修订、匹配数、影响范围和事务恢复路径，执行后以独立事务读回并报告实际结果。该决策取代旧规范中“写入/清理/破坏性操作需具体对象另行授权”的审批门，但不把无关操作纳入任务、不授权生产切换、实例或角色权限改造、Head/调度变更或超出当前目标的旧库处置。PG逻辑身份、单库单schema、集中迁移、来源只读、GET只读及测试合成数据边界继续适用。

## CHG-058：来源级板块PULSE相邻会话变化

行业与GN概念板块只对严格相邻官方会话且同一现存成员快照的完整来源级PULSE事实生成最小typed变化行。业务键绑定两端Raw捕获与内容修订、Profile修订、日历修订及板块身份；UNKNOWN保留原端点原因，未计算端点保持NOT_COMPUTED。现有板块详情通过现役API读取PG事实；HTTP不重算、不写入。变化仅描述冻结PULSE状态，不修改阈值，也不赋予正式Rotation生命周期状态。
