# 正式需求与设计变更

本文件仅记录明确的规范变化，不记录阶段任务、执行报告、测试结果或回执。

## CHG-001：新项目工作空间与交付边界

用户确定唯一源码根为G:/codex work/Stock A，交付根为G:/codex work/Stock A 交付；临时G:/codex_tmp和测试G:/codex_tmp/test_temp保持。替代此前“后续指定”和旧项目交付路径。旧V4停止开发，不迁入旧数据库、源码树或任务历史。

## CHG-002：Git仅保留业务与正式规范

用户明确禁止测试文件/脚本、阶段任务文档、阶段报告、回执和产物入Git。Git仅保留纯业务流程代码及运行必需组成、需求、设计、明确需求变更与最小根规范/仓库控制文件。此条替代旧稿“相关代码和证据一起提交”“必要小反例入Git”等冲突条款，不因审计或体积小而豁免。

测试源、fixture/Oracle及测试配置外置到现有测试根的Stock A子目录；阶段材料、执行台账、回执和产物外置交付根。规范验收条件属于设计，实际验收结果属于过程材料，二者分别存放。

## CHG-003：后续PG默认G盘、旧数据不迁移

延续用户已确认约束：新PG数据G:/Postgres/data、日志G:/Postgres/log、主动备份/导出G:/Postgres/backups。当前E:/Postgres/data保留必要可读，不自动迁移、复制、清空、初始化覆盖或切换服务。新项目启用时必须实际验证G盘路径，不以文档和PGDATA变量冒充生效。

## CHG-004：先核对算法与全链依赖，再实施新项目

主链以P00–P25的来源/身份/价格/全部研究域/Owner/索引/发布/接受后任务/实际页面合同替代粗略模块串联。每个必需字段明确生产者与消费者，缺实现不得填UNKNOWN伪装完成；后台就绪与实际显示分开，通用完成必须包含接受后observer、到期任务和当前前端确认。

算法区分Core与D0窗口/斜率/流动性、RPS单位及四类delta，MA10显式生产；定义Pure Core板块资格R2、D0四场景R2和按实际场景冻结的D2失效R2，替代未闭合legacy布尔依赖及泛指PRIOR_HIGH的旧提案。Priority采用显式有序键。以上是新项目明确设计选择，旧合同/效果不获追认，实际能力启用仍需对应采用与验证；不授权继续修补旧项目。

## CHG-005：撤销新闻及外部事件研究范围

按用户明确指令，从Stock A产品范围中移除新闻/资讯采集、外部事件催化、社会事件研究和公司/题材映射，删除相关API、表、页面及占位能力要求。撤销EVT-01至EVT-06，现行需求为136项，其余需求ID保持。第五入口从“市场与事件”改为“市场研究”，只消费指数、宽度、参与、压力、限价和风险事实。

TDX行业/概念分类和成员映射、Overlap，以及突破/失效/状态变化/跟踪/outbox等内部业务事件保留。旧参考压缩包中的历史规范保持原件身份，只读且不构成新项目任务或依赖；不以修改原件伪造其历史内容。

## CHG-006：规范按职责归档，旧代码优先复用

用户要求把设计和规范归到新项目对应文件夹，并采用能复用则复用的开发路线。136项需求正文从根SPEC的S23移至docs/requirements/产品需求.md；工程、存储、API、Windows交付、测试验收及Git边界正文移至docs/design/工程与存储规范.md。根SPEC保留稳定S编号与链接，根AGENTS继续作为自动读取的规则入口，不保留同义完整副本。

新增正式代码复用边界：解析、精确复权、正确数值内核和可拆出的产品组件优先保留；按新合同修复接口、单位、窗口和依赖。旧动态schema、万能payload、文件驱动Owner/Head、脚本依赖及历史运行壳不进入新业务链。已有正确内核不为项目换名而重写；新算法提案的采用不阻断已确定内核移植。
